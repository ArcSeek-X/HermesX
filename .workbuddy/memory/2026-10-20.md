# 2026-10-20 工作日志

## 持仓管理原型（portfolio-redesign-prototype.html）迭代
基于用户反馈，对根目录原型做了一轮结构确认与改造，最终落定的设计决策：

1. **事件记录**：确认为独立第三个页签（与持仓表格无强交互耦合，仅上下游关系），从「默认隐藏方案 b」改为常驻可见页签。
2. **新建账户**：表单改为模态框（m-new-account），与录入交互统一。
3. **指标卡**：全局资产指标卡（总权益/总市值/总现金/汇率状态）置于页签上方；风险指标卡（回撤监控/止损接近预警/口径/AI 风险信号）归属「持仓表格」页签内、操作按钮上方。维持不变。
4. **手工录入归一**：三个入口（交易数据/资金流水/公司行为）合并为一个「手工录入」模态框，内部三个独立子表单、各自提交、接口互不影响；券商 CSV 导入保持独立模态框；表格上方按钮由 4 收敛为 2（手工录入 / 券商 CSV 导入）。

实现要点：主页面签选择器已限定为 `#pageTabs .tab`，模态框内子页签复用 `.tab` 样式但独立 `switchManual` 逻辑，避免与主页签冲突。

## 账户视图联动（原型二次迭代）
经代码核查确认「全部账户」为只读汇总视图（指标卡/持仓表/事件记录均跨账户合并、CNY 口径合计；切换全部账户时 `writeBlocked=true` 禁用写入）。原型据此新增交互与约束：

1. **账户视图下拉框**：由静态 fake-select 改为真实可交互 `<select id="accountView">`，选项：全部账户 / 账户 A / B / C；默认「全部账户」。
2. **写入锁定**：`switchAccount()` 在切到「全部账户」时禁用 手工录入(btnManual)、券商 CSV 导入(btnCsv)、事件记录删除(.js-write) 三类写入操作，并展示黄色只读警示；切到具体账户后解锁，警示转绿色「已锁定到账户 X」。页面加载即执行 `switchAccount('all')`。
3. **关键约束固化**：在原型「设计决策」区块补第 ⑤ 条，明确「全部账户=只读汇总，写入操作必须禁用」，标注对应真实代码 `PortfolioPage.tsx` 的 `writeBlocked = (selectedAccount==='all')` —— 作为后续真实代码改造的重要执行点/参考点。
注：此约束与真实代码行为一致，是后续改造的硬逻辑，不是纯 UI 偏好。

## 刷新入口上提（原型三次迭代 · 方案 A）
经代码核查确认「刷新数据」按钮（handleRefresh）语义为**整页刷新**（并行重载 账户列表/快照+风险/事件记录/券商列表 + 触发决策信号），并非只刷账户视图；账户视图下拉框只是它顺带重载的第一项。用户决策采用方案 A：

1. 将「刷新数据」**上提为页面级整页刷新入口**，置于 ① 页面标题区右侧，文案改为「刷新全部」（原型加 handleRefreshDemo 做 800ms 刷新中反馈占位）。
2. 账户视图区块（②）仅保留「新建账户 / 删除账户」两个账户 CRUD 按钮，sec-tag 改为「账户视图（账户管理）」，与整页刷新职责分离。
3. 指标卡内的「刷新汇率」（handleRefreshFx）为专项按钮，粒度更小，保持独立不动。
4. 决策区块补「第 ⑥ 条」固化此决策，标注对应真实代码 handleRefresh / handleRefreshFx 映射，作为后续改造执行点。

结论：**原型现已对齐真实代码的两条独立刷新粒度** —— 整页刷新（页面级「刷新全部」）+ 汇率专项刷新（指标卡内），写入禁用（all 视图）则独立于二者。

## 账户删除可用 + 无账户空状态提示（原型四次迭代）
用户要求原型体现"无账户时提示先创建账户"等全局提示，并让"删除账户"可用（原型原先写死 disabled）。改动：

1. **账户列表改为 JS 数据驱动**（`accounts` 数组 + `renderAccountSelect()` + `currentAccount` 状态），原先静态 `<option>` 清空由脚本填充。
2. **删除账户可用**：选中**具体账户**时按钮启用，点开确认模态框（`m-delete-account`，提示不可恢复）→ 确认后从数组移除并回退到"全部账户"；选中"全部账户"时禁用（对齐真实代码 `canDeleteSelectedAccount = Boolean(writableAccountId)`）。
3. **无账户空状态提示**：`updateAccountUI()` 中当 `accounts.length===0` 时隐藏只读警示、显示"请先创建账户"全局提示（含「立即创建」入口）；删光账户即触发，新建账户后消失。对齐真实代码 `items.length===0 → setShowCreateAccount(true)`。
4. **新建账户闭环**：`createAccountDemo()` 从模态框创建账户（自动命名避免重名）并实时重渲染下拉框，使"删光→提示创建→新建恢复"形成演示闭环。
5. 原型决策区块补「第 ⑦ 条」固化上述逻辑，标注真实代码映射，作为后续改造执行点。

原型当前已覆盖的全局提示：① 全部账户只读警示 + ② 无账户创建引导 + ③ 刷新全部（页面级）。

## 设计定稿补充（最终确认）
用户在确认实施前追加两条硬约束，作为改造执行点：

1. **手工录入三子表单状态独立**：合并的「手工录入」模态框内，交易数据 / 资金流水 / 公司行为 三个子表单各自独立持有状态、互不干扰；切换内部子页签仅做显隐（不销毁 Panel），已填值各自保留；三个子表单分别调用 `handleSubmitTransaction` / `handleSubmitCash` / `handleSubmitCorporate`，提交互不牵连。
2. **事件记录删除受写入锁定**：「事件记录」页签内每条流水的「删除」按钮与手工录入 / CSV 导入同属写入型操作，一并受 `writeBlocked` 禁用——切到「全部账户」只读视图时置灰，切到具体账户后解锁。

至此 7 条决策 + 2 条补充全部固化，原型 `portfolio-redesign-prototype.html` 的「设计决策」区已追加 ⑧⑨ 对应说明，可作为 `PortfolioPage.tsx` 重构的唯一依据。实施时仍须注意三处与真实代码的出入：新建账户模态框无「备注」字段且创建后自动切换新账户、删除文案用 `text.deleteAccountMessage`（历史流水不物理删除）、三子表单提交复用既有 handler。
