## SidebarNavV2 报错排查：Invalid hook call（SidebarNavV2.tsx:140 = `<Sidebar.MenuItem>`）

排查结论（已排除项，避免重复排查）：
- **非 React 多副本**：`apps/hrs-web/node_modules` 下只有一份 `react`、一份 `react-dom`；`@heroui-pro/react` 把 react 声明为 peerDependency，不自带。
- **非版本不匹配**：react / react-dom 均为 19.2.8，react-aria-components 1.21.1，@heroui/react 3.2.4。
- **非缺少 Provider**：`@heroui-pro/react` 的 `SidebarContext` 用 `createContext(默认值)` 创建（`SidebarRoot`/`SidebarMenuItem` 都靠 `useSidebar()` 读它，有 default），所以即使 `<Sidebar>` 不在 Provider 内也不会因此崩。
- **非双 Sidebar 根冲突**：`Drawer` 在 `!isOpen` 时 `return null`，桌面端初始只有一个 `<Sidebar>` 根。

**重要项目事实：`apps/hrs-web/vite.config.ts` 启用了 `babel-plugin-react-compiler`（React Compiler）。**
它对「在渲染期被当作普通函数直接调用、但返回 JSX 的内联渲染函数」非常敏感，是 `Invalid hook call` 的高危来源。
`SidebarNavV2` 里 `renderMenuNodes` / `renderCollapseMode` / `renderGroupMode` 正是这类函数（以 `renderXxx(...)` 形式在 JSX 中调用，且 `renderMenuNodes` 在 `.map()` 中递归）。
→ 后续若复现稳定，应把它们改成真正的子组件（用 `<RenderXxx />` 渲染，而不是函数调用），这也更贴合用户「封装成组件」的意图。

**首要处置**：该报错原因 3（运行时多份 React）最常见于 Vite 依赖预构建缓存失效——本次重构给 `Shell.tsx` 和 `Docs_sideBar.tsx` 新增了 `@heroui-pro/react` 导入点，改变了依赖图。处理：停掉 dev server → 删除 `apps/hrs-web/node_modules/.vite` → 重启。

## Shell 侧栏宽度动画优化（Shell.tsx）
- 三态宽度 `SIDEBAR_WIDTH = { offcanvas:160, collapsed:64, fully:0 }`，外层 `motion.div` 动画 `width` + `overflow-hidden` 裁剪。
- **关键性能手法**：新增 `SIDEBAR_CONTENT_WIDTH = { offcanvas:160, collapsed:64, fully:64 }`，在 motion.div 内再包一层固定宽度的 `div.h-full`，宽度随状态**一次性到位**、不参与逐帧动画。这样菜单列表只在状态切换时重排一次，逐帧动画只剩裁剪，不触发列表重排。fully 沿用 64 以便与 collapsed 互切时内层零重排。
- 缓动改为 `easeOutQuint [0.22,1,0.36,1]` + `duration: 0.24`（常量 `SIDEBAR_EASE`，需显式标注元组类型否则 motion 类型报错）。**不要用 spring + bounce**：宽度过冲回弹会把菜单内容压得比目标更窄，导致抖动/文字截断。
- 通用经验：动画 `width/height` 这类 layout 属性时，让内容层尺寸与动画解耦是主要优化手段。
- **仍卡顿的根因（重要结论）**：侧栏这侧已做到逐帧零重排，但侧栏 width 每帧变 → flex 容器重算 → 右侧列(`flex-1`)宽度每帧变 → `<main>` 内整个页面内容每帧重排。**只要要求「内容区平滑变宽」，这个重排原理上无法消除**（clip-path/transform scaleX 都不行：clip-path 不改变布局占位，会导致内容区留白）。
- 若要彻底零重排，只能二选一：
  1. 内容区宽度**一次到位**（`width: calc(100% - 目标侧栏宽度)` + `shrink-0`），动画期间内容区只平移、被外层容器 `overflow-hidden` 裁剪；代价是内容区宽度瞬时变化。
  2. 侧栏改 **overlay**（absolute 脱离文档流），内容区宽度恒定；代价是侧栏浮在内容上、需背景/阴影，内容区不再变宽。
- 注意：给 `<main>` 加 `contain: layout/paint` 会使其成为 fixed/absolute 后代的 containing block，可能破坏内部弹窗/下拉定位，不要贸然加。
- `overflow-hidden` 必须保留在侧栏 motion.div 上（裁剪 + 限制逐帧 paint 区域）；时长已收到 0.2s。
