# 2026-09-12

## SidebarNavV2 / 菜单数据改造（apps/hrs-web）
- 命名约定：`NavMenuNode` 的菜单唯一标识字段已统一为 **`menuId`**（原 `menuKey`，本会话全量重命名）。数据层在 `Sidebar/menudata.ts`，组件层在 `Sidebar/SidebarNavV2.tsx`。注释明确 `menuId` 即 HeroUI Tree 节点的 `id`，用于 AlphaSift 过滤（`item.menuId !== 'screening'`）与展开键 `defaultExpandedKeys`。
- 注意事项：`apps/hrs-web/src/pages/reviewPage.tsx` 的 `handleStrategyMenuKeyDown` 仅是 `menuKey` 子串，与菜单数据无关，勿误改；v1 `SidebarNav.tsx` 用自有 `NavItem` 类型，与 `menudata.ts` 无关。
- SidebarNavV2 其他改动（同一批）：Props 新增 `className`，透传到根节点 `Sidebar.Provider`（合并基类 `hrs-sidebar-V2`）；纯分组节点（无 routePath 且含子项）标题改用 `<Sidebar.GroupLabel>{label}</Sidebar.GroupLabel>`（数据驱动），并支持一级分组的 `description` 字段作为分区标题文案。
- NavMenuNode 字段规范（最终态）：`menuId`(唯一标识/Tree id)、`menuName?`、`description`(必填，与 menuName 保持一致：menuName 是 i18n key 就写 key、是中文就写中文)、`routePath?`、`menuIcon?`、`menuBadge?`、`children?`、`exact?`、`level`(必填：0=一级分组/顶级项，1=二级子项)、`menuPosition`(必填：'header'|'content'|'footer'，默认 'content')、`menuExpanded`(必填：菜单是否默认展开，默认 false，全量已写 false)。PRODUCT_NAV_ITEMS 全为 level0/content；DEBUG_NAV_ITEMS 分组节点 level0、子项 level1，当前全部 menuPosition='content'、menuExpanded=false。
- 踩坑：手动在 menudata.ts 写示例用了中文弯引号 `‘content’`（U+2018/2019），导致 TS 语法报错；该文件只能用直引号 `'`。
- NavMenuNode 字段书写顺序约定（数据对象与类型声明均遵守）：`menuId → menuName → routePath → menuIcon → menuBadge → menuPosition → level → menuExpanded → description → (exact) → (children)`。`exact` 用户未列入顺序，作为可选尾字段放在 description 之后、children 之前（仅个别项如 home 使用）；`children` 有则带、无则省略。注意用户手写示例易把 `menuExpanded` 误拼成 `menuEexpanded`（双 E），落地时按 `menuXxx` 规范纠正为 `menuExpanded`。
- HeroUI Pro `Sidebar` 钉底技巧（SidebarNavV2.tsx，已验证）：库的 `Sidebar`/`Content`/`Footer` 在 JS 层只生成 `data-slot` 与类名，**不带任何 flex 布局样式**（`SidebarContent`=`ScrollShadow` 可滚动，`SidebarFooter`=普通 div）。要把底部设置入口固定钉在侧栏最下方、不随菜单滚动：① 设置入口从 `Sidebar.Content` 内移到 `Sidebar.Footer`；② 根 `<Sidebar className='w-full flex h-full flex-col'>`；③ `Sidebar.Content` 加 `flex-1 min-h-0`（占满剩余+自身滚动）；④ `Sidebar.Footer` 加 `shrink-0`。父容器 `hrs-container` 是 `flex h-[calc(100vh)]`，flex 默认 stretch 让 Provider 撑满全高，aside 用 `h-full` 继承。注意 Vite 日志里出现的 `Unexpected token`/`<aside> 未闭合` 多为 HMR 写入中间态残留，用 read_lints 或请求 `/src/.../SidebarNavV2.tsx` 实时转译（http=200 且无 SyntaxError 即真实通过）判定当前状态。
- 菜单分区渲染架构（SidebarNavV2.tsx，最终态，方法是内联非函数）：组件内先 `modeMenuItems = isDevelopmentMode ? DEBUG_MENU_ITEMS : PRODUCT_MENU_ITEMS`，再 `materialMenuItems = showAlphaSiftNav ? modeMenuItems : 过滤掉 menuId==='screening'`，然后按 `menuPosition` 切三份：`headerMenuItems` / `contentMenuItems`（主菜单区 `<Sidebar.Content>` 用，group/collapse 随 `menuMode`）/ `footerMenuItems`（`<Sidebar.Footer>` 动态渲染，复用 `renderGroupMode`/`renderCollapseMode`，配 `footerExpandedKeys`；**Footer 已无硬编码 settings，纯靠 footerMenuItems 数据驱动**——当前数据无 footer 项故 Footer 暂时为空，需在 menudata 给某节点设 `menuPosition:'footer'` 才会出现）。`headerMenuItems` 目前未使用（仅占位，未来 Header 区动态渲染）。早前封装的 `buildMenuItems` 方法已被用户要求撤销，改为上述内联写法。
- 默认展开逻辑（SidebarNavV2.tsx）：`defaultExpandedKeys`(content) 与 `footerExpandedKeys`(footer) 改为**按各节点的 `menuExpanded` 字段判断**（`item.menuExpanded` 为 true 才默认展开），替代原先「有 children 即展开」。因全量数据 `menuExpanded` 当前均为 false，分组默认会折叠；要让某分组默认展开，在 menudata 把对应节点的 `menuExpanded` 设为 true 即可。仅 collapse 模式受此影响（group 模式始终展开、不用该键）。`Settings2` 图标因 Footer 的硬编码 settings 入口被移除而变为未使用（lint warning，非 error）。
- 模式切换自动跳转（SidebarNavV2.tsx）：监听 `isDevelopmentMode`，仅在其「真正变化」时（用 `prevModeRef` 记录上一次值，跳过首次挂载/StrictMode 双调用）自动 `navigate` 到菜单栏第一个可跳转菜单——`contentMenuItems[0]`，若该一级含 children 则取其首个二级的 `routePath`，否则取该一级自身 `routePath`；无 `routePath` 则不跳。只针对产品/调试模式切换，**不**在 `showAlphaSiftNav` 变化时触发（用户未要求）。
