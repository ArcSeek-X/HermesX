## 本地前后端启动（运维踩坑）
- 后端必须用项目 `.venv`：`cd <repo> && .venv/bin/python main.py --serve-only`（监听 127.0.0.1:8000）。系统 `python` 不存在；`python3.11`（homebrew）缺 `litellm`，会报 `No module named 'litellm'`。
- **务必加 `WEBUI_AUTO_BUILD=false`**：否则 `main.py` 启动时会自动跑 `npm ci && npm run build` 来准备静态产物，而 `npm ci` 会破坏性清空 `apps/hrs-web/node_modules/.bin`（表现为之后 `vite: command not found`）。设 false 可跳过该步骤，只校验 artifact。
- 前端：`cd apps/hrs-web && npm run dev`（vite）。若 5173 被占用会自动顺延（1022/1023…）；后台进程跨命令会被回收，需用 `setsid`/nohup 长驻，且 `kill` 具体 PID 可能弹审批超时。
- 重复启动易留下多个 vite 实例（不同端口都 200）；清理需 kill 具体 PID。

## 启动补充（Python 版本与 macOS 差异）
- 正确 Python：项目 `.python-version` 指定 **3.11.15**（pyenv 已装，路径 `$PYENV_ROOT/versions/3.11.15/bin/python`）。系统 `/usr/bin/python3` 是 **3.9.6**，不满足 `exchange-calendars>=4.13.0` 的 `Requires-Python ~=3.10`，直接 `pip install -r requirements.txt` 会报 `No matching distribution`。必须用 pyenv 的 3.11.15 装依赖（之前 homebrew `python3.11` 缺 litellm 是因为装到了别的环境/没装全）。
- macOS 无 `setsid`：`setsid: command not found`。后台长驻进程改用 `nohup ... > log 2>&1 < /dev/null &`。
- 前端 vite 实际端口**写死 1022**（vite.config `server.port:1022`，非 5173 顺延），`/api` 代理到 `127.0.0.1:8000`。启动 `cd apps/hrs-web && npm run dev`，已验证 `http://localhost:1022/` 返回 200。
- 后端用 `uvicorn server:app --port 8000`（**不走 `main.py`**），绕开 main.py 的 `WEBUI_AUTO_BUILD` 自动 `npm ci` 清空 `node_modules/.bin` 的坑。
- 工具 `execute_command` 对长命令约 10 秒即判 "watch timeout" 返回，不能前台循环等 pip；也**不能**用 `while pgrep -f "pip install -r"` 这类前台循环等待（同样被 10 秒超时截断，pip 是独立 nohup 进程继续跑，不受影响）。
- **pip 直连官方源网络极度不稳（关键坑）**：日志大量 `RemoteDisconnected` / `SSLError ... UNEXPECTED_EOF_WHILE_READING` / `problem confirming the ssl certificate`，pip 反复重试、CPU 0% 空等，极慢（系统 py3.9 那次 4 分多钟还在 litellm 之前卡着）。**必须用国内镜像源**：`pyenv3.11 -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn`，换源后下载速度立达 30~50 MB/s。
- 当前方案（本次）：`pkill -f "pip install -r"` 杀掉卡住的旧 pip，用清华源 `nohup <pyenv3.11> -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple > /tmp/hermes_pip_mirror.log 2>&1 < /dev/null &` 后台重装（几分钟装完上百包，含 litellm-1.100.0）。装完后**已手动启动后端**：`cd <repo> && nohup /Users/gaocangxiong/.pyenv/versions/3.11.15/bin/python -m uvicorn server:app --host 0.0.0.0 --port 8000 > /tmp/hermes_backend.log 2>&1 < /dev/null &`（pid 92541，监听 8000，`/docs`=200；启动日志 `logs/api_server_20260909.log`，stdout `/tmp/hermes_backend.log`）。前端 `npm run dev` 在 1022 在线。**前后端均已起来**。
- 启动慢点提醒：uvicorn 首启会拉 LiteLLM 远程 model cost map + stock-index 远程 json，国内网 SSL 超时（仅 WARNING，自动回退本地备份），导致首次 listen 8000 多等约 10~20 秒，属正常非卡死。
- **waiter 自匹配坑（重要）**：后台等待器判断 pip 是否结束，**不能**用 `pgrep -f "pip install -r"` 或 `ps|grep "pip install -r"` 这类模式——等待器本身的 `bash -c` 命令行包含该字符串，pgrep/ps 会匹配到等待器自己，导致永远认为 pip 在跑、永远不启动 uvicorn。正确做法：启动时先 `ps -ax -o pid,command | grep "[p]ip install -r /绝对路径/requirements.txt" | awk '{print $1}'`（grep 用 `[p]ip` 字符类避免匹配 grep 自身）拿到真实 pip PID，等待器内改用 `while kill -0 <pip_pid>` 轮询（kill -0 不会自匹配）。
- **启动后端必须用 pyenv 3.11.15 绝对路径**：在 `( cd ... && nohup "$PYENV_ROOT/versions/.../python" ... )` 这种子 shell 里用 `VAR=val cmd $VAR` 时变量可能不展开，会变成 `/versions/.../python: No such file or directory`（路径残缺、pip 静默没起来，ps 查不到进程）。直接用绝对路径 `/Users/gaocangxiong/.pyenv/versions/3.11.15/bin/python` 最稳。
