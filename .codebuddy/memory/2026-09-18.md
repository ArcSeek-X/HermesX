## MenuStore 三场景重构（apps/hrs-web/src/stores/MenuStore.ts）
- 用户明确菜单数据三场景：① 首次登录 `buildMenuData(loginModuleId?)` 构建全量 menuData + 初始化 currentModuleId + 派生；② 切换模块 `setCurrentModuleId(moduleId)` 复用已持久化 menuData（不重建）+ 切 currentModuleId + 派生；③ 刷新浏览器由 store 初始化自动从 localStorage 还原（场景三，无需手动调用）。

- 约定：menuData 是路由静态派生、运行期不变，故切换模块不应重建它（否则浪费）；currentMenuData/headerMenu/contentMenu/footerMenu 为派生、不持久化。

## 修复：登录后刷新报 "Element type is invalid ... got: object"（MenuNode）
- 根因实证：lucide 图标是 `React.forwardRef` 产出的**对象**（`typeof` = object，`Object.keys` = `['$$typeof','render']`），`JSON.stringify` 恰好得到 `{}`；而 `JSON.stringify` 跳过 Symbol/函数值却**保留键名**，故 `hrs-pref-menu.menuData` 里 `menuIcon` 键幸存、值变成 `{}`。再次 `<MenuIcon />`（`src/components/layout/SideBar/MenuNode.tsx:141`）即崩溃。
- 触发链：`buildMenuData()` 接入 `LoginCard` 登录成功后才开始真正落盘，此前该函数零调用、从不写 storage，所以 bug 长期潜伏。
- 修复（MenuStore.ts 新增辅助）：`MenuIconComponent` 类型别名、`mapModuleNodes(menuData, transform)`、`stripIconsInNodes`（写前摘图标）、`buildMenuIconMap` + `applyIconsInNodes`（读后按 menuId 回填）。`applyMenuState` 的 `init` 分支落盘改为剔除图标的副本；`readStoredMenuData` 读取后先判对象形态再回填图标。
- 原则：**结构/文案以存储为权威，图标以运行时清单为唯一来源**——图标是纯代码资产，不可也不该落盘。旧脏数据会被回填覆盖，无需手动清 localStorage。
- MenuStore/MenuNode/LoginCard lint 0 错误；全量 tsc 仍有若干**与本次无关**的既有报错（StockSearch、ChatPage、DecisionSignalsPage、reviewPage、SettingsPage、StockDashboardPage 及 `router/manifest.ts:292` 的 `featureFlag` 越界属性）。
