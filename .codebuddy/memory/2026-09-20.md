# 2026-09-20 路由调试纪要

## 现象与根因
- 动态路由删除/刷新后页面落到 `errorElement` 或 404(`*` 兜底),但点击菜单能正常跳转。
- 根因:`createBrowserRouter` 在**模块加载时**对当前 URL 做初始匹配;动态路由经 `registerBusinessRoutes`→`router.patchRoutes('protected', …)` 注入发生在初始匹配之后。`patchRoutes` **不会重匹配已提交的初始导航**——所以刷新时初始匹配用空表 → 落 `*` 兜底(404)/errorElement,而点击菜单是一次新的 SPA 导航(loader 内 patchRoutes 能重匹配)故正常。
- `asyncRouterData` 由 `RouterStore` 模块加载时从 localStorage 同步还原(`initialAsyncRouterData`),故初始可拿到持久化路由。

## 修复(三处)
1. `appRouter.tsx`:`createBrowserRouter` 的 `protected.children` 初始即 `...buildProtectedRoutes(useRouterStore.getState().asyncRouterData)` + 静态 `*` 兜底 → 刷新初始匹配即含动态路由,不再 404。
2. `appRouter.tsx`:保留 `protected` 下静态 `*` 兜底,使初始匹配永远成功,不落 errorElement(运行时 patchRoutes 会用注入版 `*` 整体替换 children,不重复)。
3. `routeRegistry.tsx`:恢复 `addRouteFlag` 一次性注入守卫(`if (!addRouteFlag) return` + 注入后 `setAddRouteFlag(false)`),避免每次导航重复 patchRoutes 触发 `protected` 重渲染。登录时 `buildAsyncRouterData()` 会把 `addRouteFlag` 重置为 true,故登录后仍可注入。
4. 清理了两处调试 `alert`(`globalHook` 内、`registerBusinessRoutes` 内)。

## 调试遗留(用户已自行删 `alert` 注释)
- 用户手动删除了 `routeRegistry.tsx` 中 `// alert('是否加在动态路由…')` 注释行,导致我先前的整块替换匹配失败,已用当前内容重新恢复守卫。
