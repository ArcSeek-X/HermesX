  **2026-09-09 实测：Chip 的 `onClose` 在触发器内确实失效（用户确认）。** 根因是两条叠加：① 关闭按钮是真实 `<button>`，嵌在触发器 `<button>` 里属非法嵌套；② **Chip 只处理 `onClick`，完全没管 `onPointerDown`**——而 react-aria 的 press 由 pointerdown 驱动且会 preventDefault（`@react-aria` 下无独立 interactions 包，usePress 打包在 react-aria-components 内；已确认**没有 setPointerCapture**，不是指针捕获问题）。于是 pointerdown 先让触发器起 press → press 结束打开弹层 → 关闭按钮拿不到干净的 click（被 react-aria 对 pointerdown 的 preventDefault 抑制了兼容鼠标/click 事件，或被弹层打开后的重渲染吞掉）→ `onClose` 不执行。
  **修法必须同时做两件事（只做一件不稳）**：① 关闭按钮改成 `<span role="button">` 消除非法嵌套；② 在其上 `onPointerDown` 里 stopPropagation+preventDefault，阻止触发器起 press，弹层才不会打开、click 才能正常派发。
  **三个落地选项**：A 回退手写 span（不动共享组件）；B 给 Chip 加**可选** prop（如 `closeButtonAs?: 'button'|'span'`，默认 `'button'` 不影响现有 20+ 处），为 span 时同时挂 pointerdown 拦截（保留「用 Chip」的写法，推荐）；C 最小一行——只给 Chip 关闭按钮补 `onPointerDown={e=>e.stopPropagation()}`，可先用来验证根因，但不解决嵌套 button 非法 HTML。
  **2026-09-09 C 已实施且用户实测生效**（`Chip.tsx:148` 加 `onPointerDown={(e) => e.stopPropagation()}`）→ **根因坐实**：就是 react-aria 的 pointerdown 驱动 press 吞掉了关闭按钮的 click。**副作用评估（已查证，风险≈0）**：① 全项目**只有 2 处**用带 `onClose` 的 Chip——`HrsSelect`（新）+ `CodeTestPage.tsx:887`（演示页，父级只是普通 div）；② 全项目**没有任何 React `onPointerDown` prop**（仅 3 处命中，另两处是 ThemeSetting/UserSetting 里同名的局部变量、注册的是 `mousedown` document 监听）。故无祖先依赖 × 冒泡的 pointerdown。另注：React 合成事件 `stopPropagation()` **拦不住原生 addEventListener 监听器**（React 17+ 在根容器监听），本次能生效正因 react-aria 用的是 React props；只 stopPropagation 未 preventDefault，故**焦点/键盘 Enter-Space 触发 click 的 onClose 完全不受影响**。**遗留问题：`<button>` 套 `<button>` 非法嵌套仍在，C 只绕过症状**，彻底修需走 B。
  **⚠️ 2026-09-09 B 方案被回退**：B 是「给 Chip 加 `closeButtonAs?: 'button' | 'span'`」的可选 prop 方案（曾短暂实施：`'span'` 变体渲染 `<span role="button" tabIndex={-1}>` + pointerdown 拦截 + 自行处理 Enter/Space，且 `onKeyDown` 只能加在 span 变体避免 button 原生重复触发）。但用户澄清**那只是要方案讲解（"你打算怎么改？"），并非让我改**，故**已全部回退**：撤销 Chip 的 `closeButtonAs` 接口/解构/`renderClose` 重构 + HrsSelect 的 `closeButtonAs="span"`。教训：用户问"你打算怎么改/怎么解决"时只给方案，不要顺手落地实现。**当前停留在 C 状态**（Chip 关闭按钮 = `<button>` + `onPointerDown` 拦截，用户已实测 × 生效、弹层不打开）；button 套 button 的非法嵌套仍未根治（C 只绕过症状）。若后续用户确认要彻底消除，再实施 B。**关键取舍：不挂 `Select.Value` 的函数子节点**——`@heroui/react` 的 `Select.Value` 函数子节点拿到的不是条目数组，而是 `SelectValueRenderProps<T> & { defaultChildren }`（RAC 渲染属性对象，含 `state` / `defaultChildren` 等，没有现成的 `selectedItems`），硬转成 `readonly unknown[]` TS 报 2352 错。改用在 trigger 内**直接渲染**（不走 `Select.Value`），从 `value` + `options` 自己查 label。**× 按钮的事件与嵌套禁忌**：`HeroSelect.Trigger` 内部是 `<button>`，不能再嵌 `<button>`（无效 HTML），所以 × 用 `<span role="button" aria-label="移除">`；且 react-aria 监听的是 `onPointerDown` 触发 press 打开弹层，`onMouseDown`/click 的 stopPropagation 拦不住，必须在 `onPointerDown` 上 stopPropagation+preventDefault，同时 `onClick` 也 stopPropagation+preventDefault 后再调 `onChange(keys.slice(1))` 移除第一项（× 是「移除该项」语义，不是「清空全部」——移除后下一项顶上来，`+ N` 减 1）；`onKeyDown` 给 Enter/Space 同样处理（虽 span 无 tabIndex，但满足 jsx-a11y `click-events-have-key-events` 等 lint 规则）。**副作用**：`LiveCalendarFilter` 的「重要度」多选（之前刚换的 `HrsSelect`）现在默认就是「第一个重要度 + +N」chip 形式（chip 堆叠样式需要传 `collapseTags={false}` 才出现）。
