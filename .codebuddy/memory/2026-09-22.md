## 修复 protected 路由 errorElement 误用 StandaloneRouteBoundary（2026-09-22）
- `appRouter.tsx:60` 原 `errorElement: <StandaloneRouteBoundary/>` 是 bug：`StandaloneRouteBoundary`（`RouteBoundary.tsx`）设计用于**包裹普通页面 children**（ErrorBoundary+Suspense），它既不接收 children、也不读 `useRouteError()`；被误当数据路由 `errorElement` 时，一旦 `protected` loader 或业务页懒加载抛错，只会渲染**空白**而非错误 Modal。
- 修正：`protected.errorElement` 改为 `<RouteErrorBoundary />`（与 `/`、`/login` 一致，读 `useRouteError()` 弹错误 Modal）；同步删除失效的 `StandaloneRouteBoundary` import 与 `RouteBoundary.tsx` 中该定义（已全仓 0 引用，属冗余死代码）。
- 验证：改动文件 lint 0；`tsc -p tsconfig.app.json --noEmit` 无新增报错。
- 结论（已向用户讲清）：`NotFoundPage` 是「路由匹配」产物（`*`→`/404`），与错误边界无关；React ErrorBoundary（RouteOutletBoundary 包裹 <Outlet/>）只捕渲染期错误，数据路由 errorElement（RouteErrorBoundary）捕 loader/lazy 失败；模块顶层 throw 在 lazy import 求值阶段触发，归 errorElement（Modal）而非 Outlet 渲染边界。

## appRouter 路由优化 + 修复 404 被 patchRoutes 冲掉（2026-09-22 晚）
- 抽出 `guardAuthRedirect(request)` 共用鉴权守卫，消除 protectedLoader / 404 loader / * loader 三处雷同的「未登录→redirect('/login?redirect=...')」逻辑；顺手移除 `console.log("404")`、`console.log("*******")` 调试日志。
- 根路由扁平化：`{ path:'/', children:[{index:true,...}] }` → 顶层 `{ index:true, ... }`，少一层嵌套。
- **修复 bug**：原 `404` 路由被放进 `protected.children`，而 `RouterStore.registerAsyncRoutes` 调 `patchRoutes('protected', …)` 会整体替换 protected 的 children，登录注入后会把 `404` 冲掉。
- **用户纠正（重要）**：404 必须留在 Shell 内（底座是 Shell），不能提到顶层。因此把动态业务路由隔离到 `protected` 下的 `business` 子路由（`{id:'business', children: initialBusinessRoutes}`），`patchRoutes` 改为只替换 `'business'`（RouterStore 两处 + routeRegistry.test.ts 断言同步改 `'business'`），`404` 作为 `protected` 直接子节点固定留存、且仍在 Shell 内。404 loader 简化为 `() => null`（鉴权已由 protectedLoader 拦截）。lint 0、tsc 0、routeRegistry 单测 3/3 通过。
- **结论/约定**：404 兜底固定在 Shell(protected)内；业务路由经 RouterStore.registerAsyncRoutes 注入 protected 下的 business 子路由，patchRoutes 目标为 `'business'`。后续路由重构需保持此结构，勿再把 404 移出 protected 或改回 patchRoutes('protected')。
