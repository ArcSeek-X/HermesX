## 刷新 /home 误跳 404 的根因与修复（迭代二）
- 症状：登录后 `/home` 正常，刷新页面却匹配到顶层 `*` 兜底并 redirect /404。
- 根因：`createBrowserRouter` 在 `RouterProvider` 挂载前就对已加载 URL 做**初始匹配**；业务路由此前只靠运行时 `patchRoutes`（`App` 的 `useLayoutEffect`，晚于初始匹配）注入，初始匹配时 `protected.children` 为空 → `/home` 落到 `*` → 跳 /404，之后 URL 已变，重匹配在 /404 上不再回 /home。
- 修复：在 `appRouter.tsx` 的 `createBrowserRouter` 初始配置里，用 `buildProtectedRoutes(useRouterStore.getState().asyncRouterData)` 计算 `initialBusinessRoutes` 作为 `protected.children` 种子（`RouterStore` 模块加载即同步从 localStorage 还原 `asyncRouterData`），初始匹配即含业务路由。同时把调试期被挪进 `protected.children` 的 `404` 兜底路由移回顶层平级（否则 `registerBusinessRoutes` 的 `patchRoutes` 会整体替换 `protected.children` 把 `404` 覆盖掉，造成 `/404` 死循环）。`registerBusinessRoutes` 仍负责登录/挂载后的更新（patchRoutes 整体替换）。
- 验证：appRouter lint 0、`tsc -p tsconfig.app.json --noEmit` 0 报错；结构已复查，protected 种子 + 顶层 404/* 平级。
- 经验：RR 数据路由里「依赖持久化数据才能存在的路由」必须在初始配置即种子化，不能只靠运行时 patchRoutes。
