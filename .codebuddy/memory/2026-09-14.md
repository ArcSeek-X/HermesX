## 渐变边框（mask 方案）的坑
侧栏渐变边框用「1px 透明边框 + border-box 渐变背景 + `mask: ... padding-box` + `mask-composite: exclude`」实现（常量 `GRADIENT_BORDER_STYLE`）。
- **关键坑**：mask 会遮罩元素**及其子元素**的全部绘制内容，exclude 只留 border 区域 → 直接挂在有内容的容器（如 `aside`）上会让整个菜单不可见。必须挂在一个**独立的空图层 div**（`absolute inset-0 pointer-events-none`）上。
- 不用 `border-image`：它不支持 `border-radius`，`rounded-xl` 会退化成直角。
- Tailwind arbitrary value 对含逗号/斜杠的复杂 `mask` / `linear-gradient` 值解析不可靠，这类样式统一走 `style={{}}` 或模块常量（项目里品牌 logo 的渐变也是用 style 写的）。
- 色值一律用主题变量（`hsl(var(--primary) / 0.55)`、`var(--nav-divider)`），保证明暗自适应。
- 主题色阴影的写法：`shadow-[0_4px_24px_-4px_hsl(var(--primary)/0.22)]`（下划线转空格，直接给完整 box-shadow 值）。比 `shadow-lg shadow-primary/xx` 可靠——后者要求 `primary` 已注册进 Tailwind theme colors，否则不生成类。

## React 重复 key 警告（BK1442 板块代码）
现象：`Encountered two children with the same key, BK1442`。BK 前缀 = 板块代码。
- 根因：后端代理的东财接口（`/api/v1/sector/board-list`、`/api/v1/sector/fund-flow-sectors`）**偶发返回重复 code 的板块**，而消费方直接用 `item.code` 作 React key（`SectorBoardCards` 卡片、`SectorAnalysisPage` 的 `SectorMultiSelect` 下拉）。
- 修复：在 `api/sectorData.ts` 新增模块级 `dedupeByCode<T extends { code: string }>()`，并在 **`fetchBoardList`**（`boards` 字段）与 **`fetchSectorFundFlowSectorList`** 的返回处统一去重。数据入口去重可覆盖所有消费方（含 `StockDashboardPage`）。
- 教训：拿外部接口字段（code/symbol）当 key 时，数据源必须保证唯一；**不要用 `key={`${code}-${index}`}` 掩盖**——那会破坏组件身份复用（列表重排时状态/动画错乱），应在数据入口去重。

- 宽度与样式已统一收敛为**模块级 `THEME_CONFIG`**：`Record<SidebarTheme, { width: Record<MenuCollapsedState, number>; aside_container: Record<MenuCollapsedState, string>; aside: string }>`，pill=160/80/0（容器 p-3、fully 时 `invisible border-none`）、square=160/64/0。组件内只派生 `themeConfig = THEME_CONFIG[theme]` 再取三个值。
- ⚠️ 踩过的坑：① 嵌套对象字面量务必补逗号并同步类型，否则 vite babel 报 `Unexpected token, expected ","`；② 取容器类名要写 `themeConfig.aside_container[state]`，曾误写成 `THEME_CONFIG[theme][state]` 拿到 `undefined`（主题对象没有 offcanvas/collapsed/fully 这几个直接键）；③ 别在组件内声明与模块常量同名的 `const`（会遮蔽，模块常量变死代码）。

## SidebarNavNew 主菜单滚动边缘渐隐（scroll shadow）
参考 HeroUI Pro 的 RAC `ScrollShadow`（`scroll-shadow--fade` + `data-top-scroll`/`data-bottom-scroll` 切换 `--scroll-linear-gradient`），在 `SidebarNav-new.tsx` 主菜单滚动区实现同款效果：
- 实现：纯 React（不用 RAC）。`navRef` + `scrollFade({top,bottom})` 状态，`scroll` 监听（passive）+ `ResizeObserver`（内容增减/折叠切换引起尺寸变化时重算，observe 首次即触发）驱动；1px 容差规避亚像素误判。
- mask 三态：上缘 `linear-gradient(to bottom, transparent, black 40px)`；下缘 `black calc(100% - 40px), transparent`；两者同 `transparent, black 40px, black calc(100% - 40px), transparent`。`black`=完全可见（mask 用 alpha），常量 `SCROLL_SHADOW_SIZE = 40`（与 Pro 一致）。同时设 `maskImage` + `WebkitMaskImage`（Safari 兼容）。
- mask 挂在滚动容器（`<nav>`）自身：mask 作用于元素 border-box、随元素固定，滚动内容从下方经过即被淡出——不需要额外的遮罩层。

## 滚动边缘渐隐抽离为可复用组件 ScrollShadow（重要）
侧栏原内联的 scroll shadow 逻辑已抽成通用组件，供任意滚动面板复用：
- 新文件：`apps/hrs-web/src/components/basic/ScrollShadow.tsx`（平铺文件，与 `Card.tsx`/`Badge.tsx` 同级）；`components/basic/Index.ts` 已 `export * from './ScrollShadow'`。
- **形态：多态 B（as + forwardRef + ...rest）**——组件直接渲染滚动容器元素本身（`as` 默认 `'div'`，侧栏传 `as="nav"` 保留语义、无额外 DOM 节点）。用户拍板选组件版而非 hook 版。
- 内部：forwardRef 合并外部 ref + 内部测量 ref；`scroll` 监听（passive）+ `ResizeObserver`（容器尺寸/宽度动画变化重算）+ **每次渲染后 `useLayoutEffect` 重算**（解决菜单内容增减跨阈值后不重算、要等下次滚动才渐隐的隐患，这是相对原内联版的改进）。
- 用 `React.createElement(Tag, ...)` 渲染以规避 `ElementType` 的 JSX ref 类型问题；`style` 用 `{...style, ...shadowStyle}` 合并（调用方自己的 mask 会被组件覆盖，属预期）。
- `SidebarNav-new.tsx` 改造：删除 `SCROLL_SHADOW_SIZE` 常量、局部 `navRef`/`scrollFade`/`updateScrollFade`/effect/`scrollShadowStyle`，`<nav>` 换成 `<ScrollShadow as="nav" className="hrs-sidebar-content min-h-0 flex-1 overflow-y-auto px-2 pt-2" aria-label={...}>`，从 `'../../basic/ScrollShadow'` 引入。`React` 子导入（useCallback/useEffect/useMemo/useRef/useState）仍全部被使用，无冗余。
- 约定提醒：调用方需自行让该元素可滚动（overflow）+ 有确定高度（flex-1 min-h-0），渐隐高度由 `size` 控制（默认 40）。
- lint/tsc 对两个文件无报错。

## 组件引入路径约定（重要，避免踩坑）
- 本项目**未配置 `@/` 路径别名**：`tsconfig.app.json` 无 `paths`/`baseUrl`，`vite.config.ts` 也无 `resolve.alias`（其中的 `@` 全是 npm scope 用于拆 vendor chunk）。所以 `from '@/components'` 解析不了（TS2307）。全仓库组件引入用相对路径。
