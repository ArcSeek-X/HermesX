# 长期记忆（MEMORY.md）

## 用户偏好
- **代码注释风格**：偏好精简。删除「修改过程产物」类注释（如"已移除 XX""已移到 XX 文件""原先的 XX 联动已移除"）、与代码自明/彼此重复的冗余说明；保留有价值的 why（设计取舍、踩坑原因）与简短步骤标记（如 `// 1) 收集...`）。
- 注释语言：中英文混合项目中，中文注释做概述级补充，原有英文 docstring 原样保留。

- **避免过度封装（组件粒度）**：简单 UI 不要单独封装成组件塞进 `components/` 目录。判断标准：只是用基础组件（如 `HrsButton`）拼几个图标/文案/角标、没有独立状态与复用场景的，直接在使用它的页面里内联实现即可。例：消息日历的「筛选按钮」原封装为 `LiveCalendarFilterButton`（放在 `components/common/LiveCalendar/LiveCalendarFilter.tsx`），用户要求撤掉，改为在 `LiveCalendarPage.tsx` 直接用 `HrsButton` + lucide 图标 + `cn` 渲染，页面只保留筛选区域面板 `LiveCalendarFilterPanel`。

## 项目约定（hrs-web）
- **类型检查必须用 `npx tsc -p tsconfig.app.json --noEmit`**：根 `tsconfig.json` 是 solution 风格（`files:[]` + `references`），`tsc -p tsconfig.json` **什么都不校验**，会给出"无报错"的假象。仓库当前有大量存量错误（`@testing-library/react` 缺 `screen`/`fireEvent` 导出、HrsButton forwardRef、Pagination `xs`、PasswordInput `prefixNode` 等），校验自己改动时要按文件名过滤，别被存量错误淹没。
- **全局跨子树状态放 `contexts/` 并挂到 `App.tsx`**：头部与侧边栏是兄弟子树，需要共享状态时（如运行模式）必须在共同祖先提供 Provider。Provider 一律提供降级值（`useContext(...) ?? fallback`），保证单测不包 Provider 也能渲染。
- **抽屉组件**：统一用 `components/basic/Drawer.tsx`（HrsDrawer，HeroUI 底座）；`components/common/Drawer.tsx` 为旧版，新代码不用。
- **消息日历点击语义**：点消息 = 打开 `LiveCalendarEventDrawer` 详情抽屉（不切视图）；点日期格空白 / 日期标题 = 切到日视图看当天全部。两条路径刻意分开。
- **i18n 命名空间**：日历相关文案为 `component.LiveCalendar.*`（非 `liveCalendar.*`）；新增 key 需 zh / zh-Hant / en 三语同时补齐（`UiTextKey` 由 uiText-zh.ts 推导）。
- **消息日历筛选**：四个条件（重要度 / 类型 FE·FD / 国家 / 关键词）一律走**客户端过滤**（整月数据已在内存），在 `useLiveCalendarMonths` 的 `events` useMemo 内完成，不新增请求；与 `includeEconomicData`（后端开关，会触发重拉）是两套东西，勿混用。UI 上草稿与生效值分离，点「确认」才提交，输入过程不触发日历重算。
- **消息日历筛选重置必须返回新对象**：`LiveCalendarFilterPanel` 用引用比较（`value !== syncedValue`）把草稿拉回已生效值，因此重置/初始化默认值一律用 `createDefaultLiveCalendarFilter()`（每次新对象），不要用共享常量 `DEFAULT_LIVE_CALENDAR_FILTER`，否则「同引用 → 判定无变化 → 点了重置面板不变」。
- **国家下拉**：按中文名拼音首字母 A-Z 分组用 `pinyin-pro`（`pattern:'first'`、`toneType:'none'`、`type:'array'`），国旗取 `CalendarCountryDef.flagUri`，`HrsSelect` 分组靠数据结构（含 `options` 数组的项即识别为分组），自定义选项内容走 `renderItem`。
- **日期时间格式化**：一律复用 `utils/format.ts` 的 `formatDate` / `formatDateTime` / `formatTime`（接受秒级时间戳，内部自动 ×1000，输出固定 zh-CN 数字格式），**不要**在组件里手写 `new Date(ts*1000)` + `Intl.DateTimeFormat`。需要随 UI 语言本地化的（星期 / 月份长格式）用 `toIntlLocale(language)`——全站唯一的 locale 映射，勿在各组件重复写 zh-CN / zh-TW / en-US 三元判断。
- **新增侧边导航菜单项**：导航项由 `components/layout/SidebarNav.tsx` 的 `NAV_ITEMS` 数组驱动（顺序即菜单顺序）。新增项需在 `NAV_ITEMS` 加 `{ key, labelKey, to, icon }`，并在 `lucide-react` import 行补图标；同时必须在 `App.tsx` 顶部 `lazy` 注册页面 + `<Routes>` 加 `<Route path=... element=...>`；文案 key（`layout.nav.<x>.title` / `.description`）必须 zh / zh-Hant / en 三语同时补齐（`UiTextKey` 由 uiText-zh.ts 推导，缺任一即类型报错）。若需像「选股」那样受开关控制显隐，再在 `navItems` 过滤逻辑处理。
- **组件文档页约定**：组件演示/文档页统一放在 `apps/hrs-web/src/pages/DocsPage/Components/`，文件命名 `Docs_<组件名>.tsx`（首个文档页为 `Docs_checkbox.tsx`，路由 `/docs/component/checkbox`，菜单名「复选框」）；页面用 `<AppPage>` 包裹，演示内容参考 `CodeTestPage.tsx` 的 `HrsCheckbox` 区块风格，从 `../../../components` 与 `../../../contexts/UiLanguageContext` 引入。新增这类页面需同步在 `docs/CHANGELOG.md` 的 `[Unreleased]` 顶部加 `- [文档] ...` 条目（仓库惯例，参见 v3.28 段同类条目）。
- **基础组件目录规范**：`components/basic/` 下的组件统一采用「文件夹 + index.ts」结构（参照 HrsButton）：`<Name>/<Name>.tsx` 放实现，`<Name>/index.ts` 用 `export * from './<Name>'` 再导出（有默认导出的组件如 Chip 额外 `export { default } from './<Name>'`）。将既有平铺 `basic/X.tsx` 迁移为文件夹时，组件内部相对 import 因多一层目录要多加 `../`（`../../utils/cn` → `../../../utils/cn`，同层 `./Separator` → `../Separator`）；`basic/Index.ts` 用目录级导出（`./X` 不带文件名），迁移后无需改动，调用方用 `'../basic/X'` 或 `'../components'` 均无缝解析。
- **SideBar 目录**：侧边栏 V2（`SidebarNavV2`，基于 HeroUI Pro Sidebar）位于 `apps/hrs-web/src/components/layout/SideBar/SidebarNavV2.tsx`，同目录 `index.ts` 做桶导出（`export * from './SidebarNavV2'` + `export { default }` + `export * from './menudata'`）。外部一律从 `components/layout/SideBar` 导入，不要直接引 `SideBar/SidebarNavV2`；目录内相对导入比 `layout/` 下多一层（`../../../api/...`、`'../SidebarNav'`）。菜单数据（PRODUCT_NAV_ITEMS / DEBUG_NAV_ITEMS）已拆到同目录 `menudata.ts` 导出（`NavItem` 类型来自 `../SidebarNav`，lucide 图标仅在 menudata 内使用），SidebarNavV2 从 `./menudata` 引入；其自身的 lucide 导入仅保留 JSX 直接使用的 `BarChart3`/`Settings2`。V2 额外提供可选 `onNavigate?: () => void`（在 Provider 的 navigate 中触发），供移动端抽屉跳转后关闭；已接入 Shell 的移动端 Drawer（Shell.tsx），桌面端 aside 仍用 v1 `SidebarNav`。
- **SideBar 两级菜单约定**：菜单节点类型 `NavMenuNode`（定义在 `SideBar/menudata.ts`）一二级共用字段 `menuKey / menuName / routePath / menuIcon / children? / exact?`；`routePath` 有值才可跳转，一级为空串即纯分组（只展开）；`menuName` 传 i18n key 走 `t()`、传直写文案（如「分组一」）原样显示（`t()` 对缺失 key 实际返回 undefined，故用 `t(k as UiTextKey) || k` 兜底）；`menuIcon` 缺省传 `null`，图标插槽 CSS 固定 20px，占位仍在。HeroUI Pro 二级菜单写法：`Sidebar.MenuItem` 内嵌 `<Sidebar.MenuTrigger><Sidebar.MenuIndicator /></Sidebar.MenuTrigger>` + `<Sidebar.Submenu>{子 MenuItem}</Sidebar.Submenu>`（Submenu/MenuTrigger 内部是 Fragment 标记，子项由 RAC Tree 收成嵌套项）；`Sidebar.Menu` 传 `defaultExpandedKeys` 可默认展开分组。官方侧边栏文档站需登录抓不到，API 以 `node_modules/@heroui-pro/react/dist/components/sidebar/sidebar.d.ts` 为准。
- **CSS 变量分层（不可越界）**：主题/语义 token（`--primary`、`--foreground`、`--secondary-text`、`--radius`）与导航令牌（`--nav-item-height`、`--nav-hover-bg`、`--nav-active-bg`、`--nav-active-border`、`--nav-icon-active`）的**唯一来源是 `src/style/palette.css`**，且在 `:root` 与 `.dark` 各写一份（明暗透明度不同），组件文件不要复制/重定义，否则主题切换失效并与 v1 侧栏等共用方脱钩（`--nav-*` 同时被 `SidebarNav.tsx`、`ThemeToggle`、`UiLanguageToggle`、`kline/PeriodSelector` 使用）。`--spacing` 是 Tailwind v4 默认主题变量（`0.25rem`），属全站尺度，同理不可在组件内覆盖。组件 `.module.scss` 若要自带值，只能：① 声明在自身 class 作用域内（CSS Module 只 hash class，**不 hash 自定义属性**，写 `:root` 会全局污染）；或 ② 用 `var(--x, 兜底值)` 给回退。
- **覆盖 HeroUI Pro 样式的正确姿势**：Pro 的 CSS（`dist/css/index.css`）是**未分层**的，而 Tailwind v4 工具类在 `@layer utilities` 内——同特异性 (0,1,0) 下未分层样式永远赢，且与注入顺序无关。因此用 Tailwind 覆盖 Pro 时，凡 Pro 明确设置了冲突值的属性必须加 v4 的**后缀 `!`**（如 `flex-row! w-full! gap-3! py-3! justify-start!`；项目 tailwindcss 4.3.3，已有 `rounded-sm!` 先例）。已知会被 Pro 强制清零的位置：`.sidebar__header > *`（justify-content/gap/width/padding）；`.sidebar__header` 自身默认 `flex-direction: column` 且 padding 上下不对称（pt-4/pb-2）。另：`text-md` 在本项目有效（生成 CSS 中确有 `.text-md`），不要当无效类误删。
- **前后端启动端口与方式**：后端 FastAPI+Uvicorn 监听 `8000`（`python -m uvicorn server:app --reload --host 0.0.0.0 --port 8000`，项目根目录，需先 `source .venv/bin/activate`），API 文档 `http://localhost:8000/docs`。前端 Vite **实际端口是 `1022`**（`apps/hrs-web/vite.config.ts` 的 `server.port`，`LOCAL_RUN_GUIDE.md` 里写的 5173 已过时），不是 5173；`/api` 代理到 `127.0.0.1:8000`。启动前端需 Node v20（`nvm use 20` 或 `start-frontend.sh`）。杀进程：`pkill -f uvicorn` / `pkill -f vite` 或按端口 `lsof -ti tcp:8000` / `tcp:1022 | xargs kill -9`。注意用 `execute_command` 后台常驻启动必须 `nohup ... &`（子 shell 包裹），否则命令会被识别为 watch 在 ~10s 后提前返回、后续的 sleep 验证不会执行，但 nohup 进程本身可常驻。
- **HeroUI 3.2.4 Modal 的 PressResponder 警告坑**：`HeroUIModal.Backdrop` 内部把 children 用 `ModalContext.Provider` 包裹后传给 `react-aria-components` 的 `ModalOverlay`，而 `ModalOverlay` 内的 `Pressable` 要求直接子节点是单一可 ref DOM 元素，Provider 非 DOM 会触发 `A PressResponder was rendered without a pressable child`（错误栈归到 `Modal.tsx` 的 `HeroUIModal.Root` JSX 行，但根因在 HeroUI 库，功能不受影响，仅 console 噪音）。规避：声明式 `HrsModal` 不用 `HeroUIModal.Backdrop`，改用 `react-aria-components/Modal` 的 `ModalOverlay` 直接包裹 `HeroUIModal.Container`（Container 是 forwardRef DOM div，Pressable 子节点变为 DOM）。`Object.assign(Modal, { Backdrop: HeroUIModal.Backdrop })` 仍保留原 HeroUI Backdrop，复合用法调用方若直接用 `Modal.Backdrop` 仍会触发该警告。

- **HeroUI Pro 组件样式加载**：`@heroui-pro` 仅有 `react` 一个包（无独立 `@heroui-pro/styles`），组件样式经 `@heroui-pro/react` 的 `./css` 子路径导出（`dist/css/index.css`）。免费 `@heroui/styles` 不含 Pro 组件样式；使用 Pro 组件（如 `Sidebar`）时需在全局样式（如 `src/style/index.css`）追加 `@import "@heroui-pro/react/css";`（放在 `@import "@heroui/styles";` 之后）。项目用 Tailwind v4（`@import "tailwindcss"`，非 v3 插件），`size-*` 工具类原生可用。验证样式是否真的加载：不要 grep `heroui`（`@heroui/styles` 与 `@heroui-pro/react/css` 均不含该字面量），改用包内独有的 `[data-slot=...]` 选择器（如 Pro 的 `data-slot=sidebar-trigger`）去 dev server 返回的 `/src/style/index.css` 里 grep。
