## <a id="一适用范围与总则"></a>一、适用范围与总则

- **适用对象**：HermesX 仓库内的"方案类" markdown 文档，包括但不限于：
  - 架构决策记录（ADR，如 `backend_architecture_adr.md`）
  - 规范/约定文档（如 `FILE_FOLDER_RENAME.md`、`CODE_ANNOTATION.md`）
  - 设计/交互方案（如 `SIDEBAR_NAV_THUMB.md`）
- **不适用**：代码注释（见 `CODE_ANNOTATION.md`）、纯 README、Git 提交信息。
- 【强制】一份方案文档必须包含：**标准化文档头 + 目录 + 可跳转锚点 + 清晰正文结构**。
- 【强制】默认语言为**中文**；代码符号、文件路径、标识符保留原文并用反引号包裹。
- 【强制】文档头三要素（作者 / 更新时间 / 方案简述）不可缺，且作者固定为 `Lensgcx (GaoCangxiong) - ArcSeek-X`。
- 【推荐】单文档聚焦一个主题；跨主题拆分多篇，避免"大杂烩"。

## <a id="二文档头标准格式强制"></a>二、文档头标准格式（强制）

每份方案文档**最顶部**按以下顺序书写，顺序不可颠倒：

```markdown
# <a id="唯一锚点id"></a>方案名称标题

> 📝 **方案简述**：一句话说清这是什么、覆盖什么范围、解决什么问题、核心立场/结论是什么。
>
> 👤 **方案作者**：Lensgcx (GaoCangxiong) - ArcSeek-X
>
> 🕒 **更新时间**：yyyy-MM-dd

## 目录

- [一、章节A](#锚点a)
- [二、章节B](#锚点b)
  - [2.1 子章节](#锚点b1)

<a id="锚点a"></a>

## 一、章节A
```

要点：

1. **H1 标题**必须内嵌 `<a id="..."></a>`，id 全局唯一、稳定。
2. **方案简述**用 `📝` 块引用，紧接标题之后；要求"见题知意"，不写过程、不写废话。
3. **作者 / 更新时间**用 `👤` / `🕒` 行，写在同一个块引用内（见上模板）。
4. 更新时间在每次实质性修改时刷新为当天 `yyyy-MM-dd`。

## <a id="三目录与锚点约定强制"></a>三、目录与锚点约定（强制）

- **目录位置**：文档头（含作者/时间）之后、正文第一章之前，固定为 `## 目录`。
- **目录内容**：
  - 每个 `##` 一级章节必须在目录有一条链接；
  - `###` 子章节**建议尽量列入**（重要子章节务必可跳转，如 §3.1–§3.6）。
- **锚点机制（关键）**：跳转依赖**显式** `<a id="..."></a>`，放在对应标题**正上方**，而非依赖渲染器自动生成的中文锚点——不同查看器（GitHub / VS Code / 内部预览）的自动锚点规则不一致，中文标题极易失效。
- **id 命名约定（二选一，单文档内必须统一）**：
  - **方案 A（推荐，ASCII 稳定）**：`sec-1`、`sec-2`、`sec-3-1`、`sec-3-2`……数字对应章节号，子章节用 `父-子`。例：`SIDEBAR_NAV_THUMB.md` 所用。
  - **方案 B（沿用既有文档）**：取标题去空格/标点拼接，如 `一适用范围与总则`、`31-componentsui-组件`。
  - ⚠️ 同一文档只能选一种风格；跨文档可不同，但每篇内部自洽。
- **链接写法**：`[显示文字](#id)`，id 必须与正文某处 `<a id="id">` 完全一致。
- **回填要求**：先写正文并布好锚点，最后再回填目录链接，确保每条链接 id 与正文锚点**一一对应、无悬空**。

## <a id="四正文写作准则"></a>四、正文写作准则

- **方案简述三要素**：范围（覆盖什么）+ 目的（解决什么）+ 核心立场/结论（立场是什么）。决策类方案把结论前置。
- **结构优先**：用层级标题（`##` / `###`）拆分主题；**能用表就不用长段落**——对照表、规范表、检查清单优先。
- **代码与路径**：代码符号、文件路径、标识符一律反引号；长代码用围栏代码块并标注语言（```ts / ```python）。
- **决策先行**：结论/规定放章节开头，论证与理由放其后（参考 ADR 的"规定 + Why + How to apply"三段式）。
- **去过程化**：不堆叠变更记录、不写"本文修改于…"等过程产物；历史由 Git 承载。
- **交叉引用**：引用本/他文档章节用 `[§3.1](#sec-3-1)` 形式，改名时同步更新锚点与链接。
- **克制篇幅**：一个段落只讲一件事；避免重复标题已在说的空话。

## <a id="五强制推荐标签与决策表述"></a>五、强制/推荐标签与决策表述

- **约束等级标签**：每条规则以 `【强制】` 或 `【推荐】` 开头，明确是否必须遵照。
- **决策三段式**（用于 ADR / 关键结论）：
  - **规定/事实**：一句话立场。
  - **Why**：为何如此（背景、踩坑、约束、deadline）。
  - **How to apply**：何时生效、如何判定边界情况。
- **正反对照**：用 `✅` / `❌` 列出"值得做 / 必须避免"的清单，提升可执行性（参考 `CODE_ANNOTATION.md` 第八章）。
- **表格化约束**：多条同类规则（如命名、目录、接口）优先汇总成表，列含"规则 / 强制级别 / 现状 / 建议"。

## <a id="六执行流程"></a>六、执行流程

1. **定题与建头**：确定文档类型与标题，写 H1（含 `<a id>`）+ 方案简述 + 作者 + 更新时间。
2. **搭骨架**：规划章节结构（## / ###），先列空章节。
3. **写正文**：逐章撰写，每个 `##` / `###` 标题**正上方**插入 `<a id>`；规则标 `【强制】/【推荐】`，结论前置。
4. **回填目录**：正文完成后写 `## 目录`，逐条链接到各 `<a id>`，核对无悬空。
5. **通读校验**：检查 id 唯一、链接可达、交叉引用同步、无过期/过程产物内容。
