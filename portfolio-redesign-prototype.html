设计决策
已确认决策：① 事件记录为独立页签（第三个页签），与持仓表格无强交互耦合，作为交易流水独立查看；② 新建账户表单改为模态框（与录入交互统一）；③ 资产指标卡（总权益 / 总市值 / 总现金 / 汇率状态）为全局区块，置于页签上方；风险指标卡（回撤监控 / 止损接近预警 / 口径 / AI 风险信号）归属“持仓表格”页签内、操作按钮上方；④ 三个手工录入入口（交易数据 / 资金流水 / 公司行为）合并为一个“手工录入”模态框，内部三个独立表单、各自提交、接口互不影响；券商 CSV 导入保持独立模态框；表格上方按钮由 4 个收敛为 2 个（手工录入 / 券商 CSV 导入）。
⑤ 关键约束（已与真实代码对齐，后续改造的重要执行点）：「全部账户」本质是只读汇总视图——下方指标卡 / 持仓表格 / 事件记录均为跨账户合并汇总（CNY 口径合计）。切换到“全部账户”时，所有写入型操作必须禁用：手工录入（交易/资金/公司行为）、券商 CSV 导入、事件记录删除，均置灰不可点，并展示黄色只读警示；只有切到具体账户（账户 A / B / C）后才解锁写入，警示转为绿色“已锁定到账户 X”。对应真实代码 `PortfolioPage.tsx` 的 `writeBlocked = (selectedAccount==='all')`，原型须严格还原此行为。
⑥ 刷新入口位置（方案 A，已确认）：「刷新数据」语义为整页刷新（对应真实代码 handleRefresh：并行重载 账户列表 / 快照+风险 / 事件记录 / 券商列表，并触发 AI 决策信号刷新），并非只刷账户视图。故将其上提为页面级入口，放在 ① 页面标题区右侧（按钮文案改为「刷新全部」）；账户视图区块（②）仅保留「新建账户 / 删除账户」两个账户 CRUD 按钮，语义分离。指标卡内的「刷新汇率」为专项按钮（handleRefreshFx），粒度更小，保持独立不动。
⑦ 全局空状态与账户删除（已体现）：对齐真实代码——无账户时自动提示「请先创建账户」（真实代码 `items.length===0 → setShowCreateAccount(true)`），原型新增「无账户」全局提示（隐藏只读警示、显示创建引导 + 「立即创建」入口）；「删除账户」改为可用，仅当选中具体账户时可点（对齐 `canDeleteSelectedAccount = Boolean(writableAccountId)`，全部账户视图下禁用），经确认模态框执行，删至 0 个账户即触发上述空状态提示；账户列表改为 JS 数据驱动，新建 / 删除实时重渲染下拉框，形成「删光→提示创建→新建恢复」闭环。
⑧ 手工录入三子表单状态独立（已确认）：「手工录入」模态框内的 交易数据 / 资金流水 / 公司行为 三个子表单，各自独立持有状态、互不干扰；切换内部子页签时仅做显隐（Panel 不被销毁），已填值各自保留，不会因切换子页签而清空或串字段；三个子表单分别调用 handleSubmitTransaction / handleSubmitCash / handleSubmitCorporate，提交互不牵连。
⑨ 事件记录删除受写入锁定（已确认）：「事件记录」页签内的每条流水「删除」按钮，与手工录入 / CSV 导入同属写入型操作，一并受 writeBlocked 禁用——切到「全部账户」只读汇总视图时置灰不可点（原型以 .js-write 类在 updateAccountUI 中统一禁用），切到具体账户后解锁。
