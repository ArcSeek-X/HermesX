# 自选股管理功能设计文档

> 状态：已实现（与代码同步，2026-08-25 更新）
> 契约参考：`watchlist-api-contract.md`
> 涉及模块：后端 `api/v1/endpoints/watchlist.py` + `src/storage.py` + `api/v1/schemas/watchlist.py`；前端 `apps/hrs-web/src/{api, hooks, components, pages}`

---

## 一、背景与目标

原「自选」功能是一个扁平的股票代码数组，存储在 `system_config` 的 `STOCK_LIST` KV 中（`/api/v1/stocks/watchlist` 系列）。本模块为一套**独立的结构化自选管理**，支持：

- 自选股**分类**管理：新增 / 编辑 / 删除（逻辑删除）、分类描述、分组编码
- 分类下自选股：增删改查、移动归类、备注（`description`）、分类内排序
- 实时行情列展示（前端合并）、前端排序与搜索（拼音 / 简拼）

| 项 | 值 |
|---|---|
| 菜单名称 | `自选`（已有） |
| 路由地址 | `/watchlist`（已绑定 `WatchlistPage`） |
| 后端路由前缀 | `/api/v1/watchlist` |
| 数据库 | `data/stock_analysis.db`（SQLite） |

### 与旧方案的关系（明确边界）

- 旧自选（`STOCK_LIST` KV + `/api/v1/stocks/watchlist*`）**不修改**，仍被 `ChatPage`、设置页、`portfolio_alerts`、`Setup` 共用。
- 本模块为**新增独立模块**，使用独立 SQLite 表、独立接口前缀，并存互不干扰。

## 二、架构决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 表结构 | 分类表 + 自选股表 两张表 | 分类与股票是 1:N |
| 行情字段 | **不入库** | 高时效数据，前端按 `stock_code` 实时查询 |
| 排序与搜索 | **前端完成** | 零后端开销，复用公共组件 |
| 删除语义 | **逻辑删除**（`delete_flag`） | 可恢复、审计友好，不破坏外键 |
| 分类定位 | **`group_code`**（服务端生成、企业内唯一） | 前端不可控、稳定标识 |
| 自选股定位 | 数字 `id` | 单条记录主键 |
| 移动归类 | 后端 `move` 语义（改 `group_id`） | 保留原 `id` 与审计字段 |

## 三、数据库设计（SQLite，`stock_analysis.db`）

建表方式：沿用 `src/storage.py` 的 SQLAlchemy ORM + 幂等 `_ensure_watchlist_schema()`（`CREATE TABLE IF NOT EXISTS`），不破坏现有迁移机制。

### 3.1 表清单

| 表名 | 作用 |
|---|---|
| `stock_watchlist_group` | 自选股分类表。唯一名称、分组编码、排序权重、描述、逻辑删除与审计时间戳 |
| `stock_watchlist_item` | 自选股表。挂在某分类下，含股票代码、冗余名称、描述、分类内顺序、逻辑删除与审计时间戳 |

### 3.2 `stock_watchlist_group`（分类表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 分类唯一 ID（内部主键） |
| `name` | TEXT | NOT NULL, UNIQUE | 分类名称（唯一） |
| `sort_order` | INTEGER | NOT NULL DEFAULT 0 | 分类展示排序权重 |
| `group_code` | TEXT | NOT NULL, UNIQUE, INDEX | 分组编码（服务端生成，企业内唯一，前端不可传入） |
| `description` | TEXT | NULL DEFAULT '' | 分类描述 |
| `delete_flag` | SMALLINT | NOT NULL DEFAULT 0, INDEX | 逻辑删除标志（0 有效 / 1 已删） |
| `create_user_id` | TEXT(64) | NULL | 创建人 ID |
| `create_date_time` | DATETIME | NOT NULL | 创建时间（ISO8601，原 `created_at` 已替换） |
| `update_user_id` | TEXT(64) | NULL | 更新人 ID |
| `update_date_time` | DATETIME | NOT NULL | 更新时间（原 `updated_at` 已替换） |

> `group_code` 生成规则：`WG-{enterpriseId}-{yyyyMMdd}-{6位当日流水号}`，示例 `WG-01-20260825-000001`。
> 当前 `enterpriseId` 默认 `01`；当日流水号从 1 起、格式化为 6 位（`000001`）。
> `create_date_time` / `update_date_time` **完全替换**原 `created_at` / `updated_at`。

### 3.3 `stock_watchlist_item`（自选股表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 记录唯一 ID（前端定位自选股用） |
| `group_id` | INTEGER | NOT NULL, FK → `stock_watchlist_group(id)` ON DELETE CASCADE, INDEX | 所属分类 |
| `stock_code` | TEXT(32) | NOT NULL, INDEX | 规范股票代码，如 `600519.SH` |
| `stock_name` | TEXT(64) | NULL | 冗余股票名称（便于无网展示） |
| `description` | TEXT | NULL | 自选股描述（**原 `note` 字段已改名**） |
| `sort_order` | INTEGER | NOT NULL DEFAULT 0 | 分类内展示顺序 |
| `delete_flag` | SMALLINT | NOT NULL DEFAULT 0, INDEX | 逻辑删除标志（0 有效 / 1 已删） |
| `create_user_id` | TEXT(64) | NULL | 创建人 ID |
| `create_date_time` | DATETIME | NOT NULL | 创建时间 |
| `update_user_id` | TEXT(64) | NULL | 更新人 ID |
| `update_date_time` | DATETIME | NOT NULL | 更新时间 |

**联合唯一约束**：`UNIQUE(group_id, stock_code)` —— 同一分类下股票不重复。

> 删除分类采用**逻辑删除**，级联删除其下自选股也走逻辑删除（`delete_flag=1`），不依赖外键物理 `ON DELETE CASCADE`；外键 CASCADE 仅作兜底。

### 3.4 分组编码生成规则（服务端）

| 项 | 规则 |
|---|---|
| 格式 | `WG-{enterpriseId}-{yyyyMMdd}-{6位流水号}` |
| enterpriseId | 暂固定 `01`（企业维度能力未实现前默认值） |
| 日期 | 创建当日 `yyyyMMdd` |
| 流水号 | 当日从 1 起，格式化为 6 位（`000001` ~ `999999`） |
| 示例 | `WG-01-20260825-000001` |
| 生成时机 | `POST /create_group` 由后端计算并写入，前端不可传入 |

## 四、服务端接口设计

模块：`api/v1/endpoints/watchlist.py`，前缀 `/api/v1/watchlist`（由 `api/v1/router.py` 挂载）。
排序与搜索由前端完成，服务端仅负责 CRUD 与分类级数据返回。

### 4.1 接口清单（语义化）

| 方法 | 路径 | 关键入参 | 响应 | 说明 |
|---|---|---|---|---|
| GET | `/get_group_list` | 无 | `List[WatchlistGroupList]` | 列出未删除分类（按 `sort_order`），含实时 `item_count` |
| POST | `/create_group` | body: `name, description?, sortOrder?` | `WatchlistGroupList` | 新增分类；自动生成 `group_code`；名称重复 409 |
| POST | `/update_group` | body: `group_code, name?, description?, sortOrder?` | `WatchlistGroupList` | 编辑分类（按 `group_code` 定位） |
| DELETE | `/delete_group/{group_code}` | 路径 `group_code` | `{ success: bool }` | 删除分类（逻辑删除，级联逻辑删除其下股票） |
| POST | `/get_items_list` | body: `groupId, pageSize, pageNum` | `WatchlistItemsPaginatedResponse` | 分页查询某分类自选股 |
| POST | `/create_item/{id}` | 路径 `id`=groupId；body: `stockCode, stockName?, description?` | `WatchlistItemOut` | 新增自选股；同分类重复 409 |
| POST | `/update_item/{id}` | 路径 `id`=itemId；body: `description?, stockName?` | `WatchlistItemOut` | 编辑备注/名称 |
| DELETE | `/delete_item/{id}` | 路径 `id`=itemId | `{ success: bool }` | 删除自选股（逻辑删除） |
| PUT | `/move_item/{id}` | 路径 `id`=itemId；body: `target_group_id` | `WatchlistItemOut` | 移动归类（改 `group_id`） |

> 已删除接口：`GET /groups/{id}/items`（`list_items`）—— 前端统一走分页查询 `get_items_list`，不再提供全量接口。

### 4.2 请求 / 响应 Schema（`api/v1/schemas/watchlist.py`）

| Schema | 用途 | 关键字段 |
|---|---|---|
| `WatchlistGroupCreate` | 新增分类 | `name`(必填), `description?`, `sort_order?` |
| `WatchlistGroupUpdate` | 编辑分类 | `group_code`(必填, 定位), `name?`, `description?`, `sort_order?` |
| `WatchlistGroupList` | 分类列表项 | `id, name, description, group_code, item_count, sort_order, create_date_time, update_date_time` |
| `WatchlistItemCreate` | 新增自选股 | `stock_code`(必填), `stock_name?`, `description?` |
| `WatchlistItemUpdate` | 编辑自选股 | `description?`, `stock_name?` |
| `WatchlistItemMove` | 移动归类 | `target_group_id`(必填) |
| `WatchlistItemOut` | 自选股响应 | `id, group_id, stock_code, stock_name, description, sort_order, create_date_time, update_date_time` |
| `WatchlistItemsQueryRequest` | 分页查询请求 | `group_id`(必填), `pageSize`(默认20), `pageNum`(默认1) |
| `WatchlistItemsPaginatedResponse` | 分页查询响应 | `list, total, pages, pageNum, pageSize` |
| `SimpleSuccess` | 通用成功 | `success: bool` |

> 前端请求体发送 snake_case（`group_code` / `stock_code` / `target_group_id`），响应经 `toCamelCase` 归一化为 camelCase。

### 4.3 失败处理约定

| 场景 | 状态码 |
|---|---|
| 分类 / 自选股不存在 | `404` |
| 分类名重复 / 同分类股票重复 / 移动目标已存在该股票 | `409` |
| 股票代码无效或未收录（新增时校验） | `400` |
| 参数校验失败（如分类名为空） | `422` |

- 所有删除为**逻辑删除**（`delete_flag=1`），非物理删除。
- 删除分类：级联将其下自选股置 `delete_flag=1`。

## 五、前端设计

### 5.1 页面结构（`WatchlistPage.tsx`）

左右两侧均用 `AnimCard` 卡片容器包裹。

```
┌──────────────────┐  ┌──────────────────────────────────────────────┐
│ 左侧 AnimCard     │  │ 右侧 AnimCard                                  │
│ 分组列表(ListCard)│  │ 标题：xxx分组                                   │
│ 新增/编辑/删除    │  │ [排序▾]      [搜索框]    [+ 新增]               │
│ (group_code 定位) │  │ 表格：名称/现价/涨跌/成交/换手/市值/备注/操作   │
└──────────────────┘  └──────────────────────────────────────────────┘
```

### 5.2 左侧分类区（`WatchlistGroupPanel.tsx`）

| 能力 | 实现 |
|---|---|
| 分类卡片 | 复用 `ListCard`：标题=`name`、描述=`description`、右侧 Chip=`item_count`（个股数量） |
| 新增 / 编辑 | 弹框表单「分类名称」(必填) + 「分类描述」(选填)，新增与编辑复用同一弹框 |

### 5.3 右侧列表区（`WatchlistStockTable.tsx`）

| 区域 | 实现 |
|---|---|
| 卡片容器 | `AnimCard` |
| 标题 | 当前选中分类名称 |
| 排序 | 前端本地排序（默认 / 涨幅 / 成交额 / 换手率 / 市值） |

## 六、接口 / 前端 API / Hook / 功能说明 四方对照

| 服务端接口 API（最新路径） | 前端请求 API（`api/watchlist.ts`） | 前端 Hook（`useWatchlistManager.ts`） | 功能说明 |
|---|---|---|---|
| `GET /api/v1/watchlist/get_group_list` | `getWatchlistGroups()` | `loadGroups()` | 列出未删除分类，按 `sort_order` 升序，实时 `COUNT` 每个分类 `item_count` |
| `POST /api/v1/watchlist/create_group` | `createWatchlistGroup(name, description?)` | `createWatchlistGroup(name, description?)` | 新增分类，服务端生成 `group_code`，名称唯一校验 |
| `POST /api/v1/watchlist/update_group` | `updateWatchlistGroup({groupCode, name?, description?, sortOrder?})` | `updateWatchlistGroup(groupCode, {name?, description?})` | 编辑分类（按 `group_code` 定位），刷新 `update_date_time` |
| `DELETE /api/v1/watchlist/delete_group/{group_code}` | `deleteWatchlistGroup(groupCode)` | `deleteWatchlistGroup(groupCode)` | 删除分类（逻辑删除，级联逻辑删除其下股票） |
| `POST /api/v1/watchlist/get_items_list` | `getWatchlistItems(groupId, pageNum, pageSize)` | `getWatchlistItems(groupId, pageNum, pageSize)` → `loadItems` | 分页查询某分类自选股，返回 `list/total/pages/pageNum/pageSize` |
| `POST /api/v1/watchlist/create_item/{id}` | `createWatchlistItem(groupId, {stockCode, stockName?, description?})` | `addItem(groupId, {stockCode, stockName?, description?})` | 新增自选股，校验代码合法性、分类存在、同分类不重复 |
| `POST /api/v1/watchlist/update_item/{id}` | `updateWatchlistItem(id, {description?, stockName?})` | `editItemDescription(id, description)` | 编辑备注 / 名称，刷新 `update_date_time` |
| `DELETE /api/v1/watchlist/delete_item/{id}` | `deleteWatchlistItem(id)` | `removeItem(id)` | 删除自选股（逻辑删除） |
| `PUT /api/v1/watchlist/move_item/{id}` | `moveWatchlistItem(id, targetGroupId)` | `moveItem(id, targetGroupId)` | 移动归类，校验目标分类存在、目标分类下不重复 |

**命名语义统一规则**：`create`=新增；`update`=修改更新；`delete`=删除（逻辑删除）；`get`=查询；`move`=移动。

**定位字段**：分类用 `group_code`，自选股用数字 `id`。

## 八、验证计划

| 层 | 命令 / 方式 | 说明 |
|---|---|---|
| 后端 | `python -m py_compile api/v1/endpoints/watchlist.py` | 编译通过 |
| 后端 | 离线接口自测 | 验证 CRUD、逻辑删除、级联、唯一约束、`group_code` 生成、错误码 |
| 前端 | `cd apps/hrs-web && npm run lint && npm run build` | 构建与 lint 通过 |
| 手动 | 浏览器 `/watchlist` | 分类增删改（含 `group_code` 生成）、列表行情、排序、搜索、新增、移动 |

**风险点**：

- 实时行情批量拉取可能慢 / 失败 → 列表 loading + 容错（行情缺失显示「—」）。
- 拼音 / 简拼搜索依赖 `useStockIndex` 数据完整性。
- 逻辑删除下「已删除分类」不应出现在列表（后端 `delete_flag=0` 过滤）。
- 移动归类重复判定（目标分类已存在同一股票）返回 409，前端需提示冲突。

## 九、关键设计点（评审确认项，均已落地）

1. **逻辑删除**：分类与自选股均 `delete_flag` 软删，可恢复、审计友好。
2. **分组编码 `group_code`**：服务端生成、企业内唯一、前端不可传入；作为分类定位主键。
3. **`note` → `description`**：自选股描述字段统一改名，前后端一致。
4. **时间戳替换**：`created_at` / `updated_at` 完全替换为 `create_date_time` / `update_date_time`。
5. **分类级联删除**：删除分类级联逻辑删除其下股票（非物理删）。
6. **Hook 命名 `useWatchlistManager`**：与旧 `useWatchlist.ts` 区分，避免冲突。
