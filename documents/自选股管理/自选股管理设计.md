# 自选股管理功能设计文档

> 状态：方案评审稿（待评审，未开始实现）
> 日期：2026-08-18

## 一、背景与目标

当前「自选」功能是一个**扁平的股票代码数组**，存储在 `system_config` 的 `STOCK_LIST` KV 中（接口 `/api/v1/stocks/watchlist` 系列）。该模型无法支撑分类管理、备注、行情列、排序与搜索等需求。

本方案新增一套**结构化自选管理**：支持自选股分类（新增/编辑/删除）、分类下自选股的增删改查与**移动归类**、实时行情列展示、前端排序与搜索、备注，以及新增自选股并落库。

- 菜单名称：`自选`（已有）
- 路由地址：`/watchlist`（已绑定 `WatchlistPage`）
- 菜单映射（现有 `App.tsx`）：`{ key: 'watchlist', label: '自选', path: '/watchlist', icon: <StarOutlined /> }`

### 与旧方案的关系（明确边界）

- 旧自选（`STOCK_LIST` KV + `/api/v1/stocks/watchlist*` 接口）**本次不修改**，它仍被 `ChatPage` 加自选、设置页基础配置、`portfolio_alerts` 组合告警、`Setup` 自检共用。
- 本方案是**新增独立模块**，使用独立 SQLite 表、独立接口前缀 `/api/v1/watchlist`，与旧方案并存，互不干扰。

---

## 二、架构决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 表结构 | **分类表 + 股票表**两张表 | 分类与股票是 1:N 关系，单表无法表达分类增删改语义 |
| 行情字段是否入库 | **不入库** | 现价/涨跌幅/成交额/换手率/总市值是高时效数据，入库会产生脏数据；通过股票代码实时查询 |
| 排序与搜索位置 | **前端完成** | 需求明确：复用公共组件、零后端开销；前端已持有实时行情与本地股票索引 |
| 新模块 vs 改造旧接口 | **新建独立模块** | 不破坏旧 `STOCK_LIST` 及其调用方，降低回归风险 |
| 移动归类 | **支持** | 股票可在分类间移动（相当于"从 A 删除 + 加到 B"，或后端提供 move 语义） |
| 旧数据迁移 | **不迁移** | 旧 `STOCK_LIST` 是扁平数组，结构不同，独立新功能 |

## 三、数据库设计（SQLite，库 `stock_analysis.db`）

建表方式：沿用 `src/storage.py` 现有模式——定义 SQLAlchemy ORM Model，在 `_init_database()` 中新增幂等的 `_ensure_watchlist_schema()`（`CREATE TABLE IF NOT EXISTS` + 兼容旧库检查），不破坏现有迁移机制。两张表通过外键级联删除关联。

### 表清单

| 表名 | 作用 |
|---|---|
| `stock_watchlist_group` | 自选股分类表。每个分类有唯一名称、排序权重、时间戳。支持新增/编辑/删除 |
| `stock_watchlist_item` | 自选股表。每条记录挂在某个分类下，含股票代码、冗余名称、备注、分类内顺序、时间戳。同一分类下股票代码唯一，可移动到其它分类 |

### `stock_watchlist_group`（分类表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 分类唯一 ID |
| `name` | TEXT | NOT NULL, UNIQUE | 分类名称，唯一 |
| `sort_order` | INTEGER | NOT NULL DEFAULT 0 | 分类展示排序权重 |
| `created_at` | TEXT | NOT NULL | 创建时间（ISO8601） |
| `updated_at` | TEXT | NOT NULL | 更新时间（ISO8601） |

### `stock_watchlist_item`（自选股表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 记录唯一 ID |
| `group_id` | INTEGER | NOT NULL, FK → stock_watchlist_group(id) ON DELETE CASCADE | 所属分类 |
| `stock_code` | TEXT | NOT NULL | 规范股票代码，如 `600519.SH` |
| `stock_name` | TEXT | NULL | 冗余股票名称，便于无网/行情失败时的展示 |
| `note` | TEXT | NULL | 用户备注 |
| `sort_order` | INTEGER | NOT NULL DEFAULT 0 | 分类内展示顺序 |
| `created_at` | TEXT | NOT NULL | 创建时间（ISO8601） |
| `updated_at` | TEXT | NOT NULL | 更新时间（ISO8601） |

**联合唯一约束**：`UNIQUE(group_id, stock_code)` —— 同一分类下股票不重复。

**索引建议**：`idx_watchlist_item_group (group_id)` 提升按分类查询性能。

**移动归类实现**：将某 `item` 的 `group_id` 改为目标分类 ID（若目标分类已存在该股票则返回冲突）。等价于"改归属分类"，无需删除重建，保留原 `id`/`note`/`created_at`。

## 四、服务端接口设计

新增模块：`api/v1/endpoints/watchlist.py`，路由前缀 `/api/v1/watchlist`，在 `api/v1/router.py` 挂载。

> 排序与搜索由前端完成，因此服务端接口**仅负责 CRUD 与分类级数据返回**，不在服务端做行情排序或股票搜索。

### 接口清单

| 方法 | 路径 | 请求参数 | 响应 | 说明 |
|---|---|---|---|---|
| GET | `/groups` | 无 | `List[WatchlistGroupOut]` | 列出所有分类（按 `sort_order` 排序） |
| POST | `/groups` | body: `{ name: string }` | `WatchlistGroupOut` | 新增分类；`name` 重复返回 409 |
| PUT | `/groups/{id}` | body: `{ name?: string, sort_order?: int }` | `WatchlistGroupOut` | 编辑分类名/排序 |
| DELETE | `/groups/{id}` | 无 | `{ success: bool }` | 删除分类；级联删除其下股票 |
| GET | `/groups/{id}/items` | 无（搜索/排序前端做） | `List[WatchlistItemOut]` | 取某分类下所有股票（按 `sort_order`） |
| POST | `/groups/{id}/items` | body: `{ stock_code: string, stock_name?: string, note?: string }` | `WatchlistItemOut` | 新增股票到分类；同分类重复返回 409 |
| PUT | `/items/{id}` | body: `{ note?: string, stock_name?: string }` | `WatchlistItemOut` | 修改备注/名称 |
| DELETE | `/items/{id}` | 无 | `{ success: bool }` | 删除某自选股 |
| PUT | `/items/{id}/move` | body: `{ target_group_id: int }` | `WatchlistItemOut` | **移动归类**：改 `group_id`；目标分类已含该股票返回 409 |

### 请求/响应 Schema（`api/v1/schemas/watchlist.py` 新建）

```python
class WatchlistGroupCreate(BaseModel):
    name: str = Field(..., min_length=1, max_length=50)

class WatchlistGroupUpdate(BaseModel):
    name: Optional[str] = Field(None, min_length=1, max_length=50)
    sort_order: Optional[int] = None

class WatchlistGroupOut(BaseModel):
    id: int
    name: str
    sort_order: int
    created_at: str
    updated_at: str

class WatchlistItemCreate(BaseModel):
    stock_code: str = Field(..., min_length=1, max_length=32)
    stock_name: Optional[str] = None
    note: Optional[str] = Field(None, max_length=255)

class WatchlistItemUpdate(BaseModel):
    note: Optional[str] = Field(None, max_length=255)
    stock_name: Optional[str] = None

class WatchlistItemMove(BaseModel):
    target_group_id: int

class WatchlistItemOut(BaseModel):
    id: int
    group_id: int
    stock_code: str
    stock_name: Optional[str]
    note: Optional[str]
    sort_order: int
    created_at: str
    updated_at: str
```

### 失败处理约定

- 分类/股票不存在：`404`
- 分类名重复 / 同分类股票重复 / 移动目标已存在该股票：`409`
- 参数校验失败：`422`（FastAPI 默认）
- 删除分类时级联删除股票（依赖外键 `ON DELETE CASCADE`）；需确认 SQLite 已 `PRAGMA foreign_keys=ON`

### 5.2 左侧分类区实现

封装为**分类组件**（`components/watchlist/WatchlistGroupPanel.tsx` 新建）：

- 顶部「分组」标题 + **新增分组**：一个输入框 + 「新增」按钮，回车或点击提交 `POST /groups`。
- 下方一层平铺的分类列表（非树状）。
- 鼠标移入每条分类，显示「编辑 ✎」「删除 🗑」图标：
  - 编辑：内联或可弹出的输入框修改名称 `PUT /groups/{id}`。
  - 删除：走现有 `Modal`/confirm 模式，`DELETE /groups/{id}`（级联删股票）。
- 选中态高亮当前分类，点击切换右侧列表。

## 七、验证计划

| 层 | 命令 | 说明 |
|---|---|---|
| 后端 | `./scripts/ci_gate.sh` | 含 py_compile / lint / 离线测试 |
| 后端 | 离线接口自测（curl/pytest） | 验证 CRUD、move、唯一约束、级联删除、错误码 |
| 前端 | `cd apps/hrs-web && npm run lint && npm run build` | 构建与 lint 通过 |
| 手动 | 前端页面走查 | 分类增删改、列表行情、排序、搜索、新增落库、移动归类 |

**风险点**：
- 实时行情批量拉取可能慢/失败 → 列表需 loading + 容错（行情缺失显示「—」）。
- 拼音/简拼搜索依赖前端本地股票索引 `useStockIndex` 数据完整性。
- 级联删除需确认 SQLite 外键已开启（`PRAGMA foreign_keys=ON`）。
- 移动归类的并发/重复判定（目标分类已存在同一股票）需前端先查重提示。

## 八、待评审决策点（请在评审时确认）

1. **旧数据迁移**：确认不迁移旧 `STOCK_LIST`，两套并存（默认确认）。
2. **分类级联删除**：删除分类时其下股票一并删除（不可恢复），是否接受？
3. **`stock_name` 冗余字段**：入库时是否由前端/服务端在新增时写入名称（便于无网展示）？
4. **默认排序语义**："默认"按 `sort_order`（添加顺序）还是添加时间？默认 `sort_order`。
5. **移动归类交互**：移动时若目标分类已含该股票，是提示冲突（409）还是自动合并？默认提示冲突。
6. **新 hook 命名**：为避免与旧 `useWatchlist.ts` 冲突，新 hook 命名为 `useWatchlistManager.ts`，是否同意？
