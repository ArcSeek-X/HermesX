## 一、Context（背景与目标）

在个股 K 线页搜索框下方提供"最近搜索"列表，满足以下诉求：

- 用户每次在 K 线页搜索，或从其他页面（自选股表格、顶栏搜索栏、Scanner、尾盘选股等）携带股票跳转过来，均在列表留下记录。
- 列表展示最近 10 条，新搜索顶到队首、重复搜索去重顶置（滚动队列）。
- 列表支持「一键清除」。
- 卡片视觉对齐 `EodStockCard.tsx`（保留「加自选」按钮与迷你走势图），后续与用户做细节微调。
- 行情数据实时拉取（准确），但必须做性能优化，避免每挂载一次产生大量请求。

**覆盖范围**：新增持久化表、后端 `recent-search` 一组 CRUD 接口、前端列表/卡片组件与 Hook、K 线页接入记录逻辑、i18n。

**不覆盖**：跳转入口本身的改造（已由《跳转个股 K 线页统一方案》统一为 `?stockCode=`，本方案直接复用，不新增改动）；K 线图数据接口与渲染。

## 二、记录时机与数据流转

<a id="sec-2-1"></a>

### 2.1 统一入口与去噪

**规定**：所有"搜索/跳转查看某只股票"的入口最终都落到 `/stock/kline?stockCode=<code>` 并触发 `StockKLinePage.loadStockData`，因此**记录逻辑只集中在 K 线页**，无需改动任何跳转方代码即可满足"无论在哪个页面跳转过来都会记录"。

**去噪（避免误记）**：区分显式搜索与隐式重载，仅以下两类触发记录：

| 触发类型 | 入口 | 是否记录 |
| --- | --- | --- |
| 显式搜索 | 页内 `handleSearchSubmit`（手动输入并搜索） | ✅ |
| 显式跳转 | `searchParams` 变化带来的 `?stockCode=` 直达（自选股/顶栏/Scanner/EodPicker 等） | ✅ |
| 隐式重载 | `handlePeriodChange` / `handleFullDataToggle` / `loadMoreHistory`（切周期/开全量/左滑翻页） | ❌ 不记录 |

**实现要点**（在 `StockKLinePage.tsx`）：

- 新增 `pendingRecordCodeRef`：显式入口发起加载前置为本次代码。
- `loadStockData` 成功分支：若 `pendingRecordCodeRef` 与本次加载代码一致，直接调用 `recordRecentSearch({ stockCode, stockName })` 落库并清除标记；名称取自已归一化的 `stockInfo.name`。**记录动作收口在页面，不经过列表组件**——列表会被条件卸载，经组件 prop 传递记录请求会丢失。
- 同代码短期内重复搜索：由表 `UNIQUE(user_id, stock_code)` + upsert 去重并刷新 `update_date_time`（顶置），不会插入重复行。

**显示时机**（按评审确认的交互）：

| 状态 | 最近搜索列表 | 行情卡 / K 线卡 | 其它 |
| --- | --- | --- | --- |
| 搜索框清空 / 未选中股票 | 显示（搜索引导） | 隐藏 | 移除原 `kline.noStockSelected` 空态提示，由列表空态承担 |
| 查询成功（`stockInfo` 有值） | 隐藏 | 显示 | 行情加载失败时仅在列表上方透出错误文案 |

列表以 `!stockInfo` 条件渲染；清空搜索框后重新挂载会重新读 `list`，因此刚落库的记录自然出现在队首。

<a id="sec-2-2"></a>

### 2.2 滚动队列与去重语义

- 每用户保留最近 10 条，按 `update_date_time` 倒序。
- 记录时已存在同 `(user_id, stock_code)`：更新 `stock_name`/`market`/`update_date_time`，顶到队首。
- 记录时不存在：插入新行。
- 写入后超出 10 条的旧行由仓储 `trim` 删除（保留倒序前 10），避免无限增长。
- 一键清除：`DELETE WHERE user_id = ?`，清空该用户全部记录。

## 三、数据库表设计

表名：`stock_recent_search`（命名对齐 `stock_watchlist_*`）。**已加 `user_id` 列、已移除 `source` 列**（按评审结论）。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | Integer | PK, autoincrement | 自增主键 |
| `user_id` | String(64) | NOT NULL, default `'default'`, index | 用户标识；当前单用户本地应用统一填 `'default'`，预留多用户扩展 |
| `stock_code` | String(32) | NOT NULL, index | 纯代码（`600519` / `hk00700` / `AAPL`），跨市场等价归一在业务层完成 |
| `stock_name` | String(64) | NULL | 记录时的名称快照（兜底展示，实时价格以实时行情为准） |
| `market` | String(16) | NULL | 市场段 `cn` / `hk` / `us`，由代码归一推导，可选 |
| `create_date_time` | DateTime | NOT NULL, default `utc_naive_now` | UTC naive，首次记录时间 |
| `update_date_time` | DateTime | NOT NULL, default `utc_naive_now`, onupdate | 最近一次记录时间，排序键 |

**约束**：`UniqueConstraint('user_id', 'stock_code', name='uix_recent_search_user_code')`。

**建表与迁移**：模型注册到 `src/infrastructure.persistence.base.Base` 后，由现有启动期 `Base.metadata.create_all`（`src/storage.py`）自动建表；属新增表，**无需 bump `CURRENT_SCHEMA_VERSION`**（仅破坏性变更才 bump）。模型须在 `src/infrastructure/persistence/models/__init__.py` 登记，否则建表静默漏表。

**`market` 推导**（可选，写入时算好）：`cn`（A 股 `6/0/3/8/4` 开头或 `.SH/.SZ`）、`hk`（`.HK` 或 `00700` 形态）、`us`（纯字母如 `AAPL`）。

## 四、后端接口设计

路由前缀：`/api/v1/recent-search`（在 `api/v1/router.py` 注册，tag `RecentSearch`）。
约定：请求体 snake_case，响应 snake_case，前端统一 `toCamelCase`（与 `watchlist.ts` 一致）。`user_id` 当前由请求体可选传入、默认 `'default'`；接入统一鉴权后改为从会话取。

<a id="sec-4-1"></a>

### 4.1 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/recent-search/list` | 列出当前用户最近搜索（最多 10 条，倒序） |
| POST | `/api/v1/recent-search/record` | 记录/更新一条搜索（upsert + trim） |
| DELETE | `/api/v1/recent-search/clear` | 一键清空当前用户记录 |

<a id="sec-4-2"></a>

### 4.2 请求/响应格式

**GET `/list`** → `200`：

```json
{
  "items": [
    {
      "id": 1,
      "user_id": "default",
      "stock_code": "600519",
      "stock_name": "贵州茅台",
      "market": "cn",
      "create_date_time": "2026-11-10T02:13:00",
      "update_date_time": "2026-11-10T03:20:00"
    }
  ]
}
```

**POST `/record`** 请求体：

```json
{ "stock_code": "600519", "stock_name": "贵州茅台", "market": "cn" }
```

响应 `200`：返回被记录/更新的条目 `{ "item": { ... } }`。校验：空 `stock_code` → 422。

**DELETE `/clear`** → `200`：`{ "success": true }`。

<a id="sec-4-3"></a>

### 4.3 性能：批量行情与分时接口

为支持卡片实时行情 + 迷你走势图，且避免对 10 张卡片各发 1 次请求（10 次 quote + 10 次 timeline = 20 次），**新增批量接口**：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/stocks/batch-quote` | 批量实时行情，body `{ "codes": [...] }`，最多 10 个；复用既有 `get_realtime_quote`，同步端点内用 `ThreadPoolExecutor` 并发取，返回**规范 camelCase 行情数组**（字段口径见 §4.4，含 `amplitude` / `peRatioTTM` / `totalMarketCap`）。响应 `code` 统一取请求代码，避免数据源回带后缀导致前端无法按代码合并 |
| POST | `/api/v1/stocks/batch-timeline` | 批量当日分时，body `{ "codes": [...] }`；复用 `fetch_intraday_timeline` + 进程内缓存（TTL 120s），返回**下采样**（约 48 点）的 `points` 与 `prevClose`。取数为「stock-sdk 桥接优先 + 东财直连回退」（`push2his` 在部分网络会被直接断连，桥接 10 只并发实测约 0.54s 且全部有数据）；批量 10 只一次并发、回退直连单次短超时不重试，并以 0.9s 整体 deadline 兜底；超时/失败的单只降级为空点列，线程池非阻塞关闭，接口不被上游拖住 |

> 说明：行情批量接口走 **`/stocks/quote` 域**（而非 `/kline/info`）。既有单只 `/stocks/{code}/quote` 缺 `amplitude` / `pe_ratio_ttm` / `total_market_cap`，需按 §4.4 在 service + schema 层补齐，并使响应字段与前端 `StockQuoteCore` **同名（camelCase，如 `totalMarketCap`）**；前端可直接 `Pick<StockQuoteCore>` 消费，无需再经 `toCamelCase` / `quoteFromStockQuote` 二次适配。

前端列表只需 **3 次请求**（list + batch-quote + batch-timeline）即可渲染 10 张卡片，替代 21 次。批量接口对 `codes` 长度做上限校验（≤10），空数组直接返回空。

<a id="sec-4-4"></a>

### 4.4 字段命名统一规范（数据层 → 服务层 → 前后端）

外部数据源（东方财富 / AKShare / 腾讯等）字段名差异大（如总市值可能是 `total_market_cap` / `totalMarketCap` / `mktcap`）。为避免各层各自命名、出现 `current_price → currentPrice → price` 三重映射，定义**单一真源领域模型 `StockQuoteCore`**（`apps/hrs-web/src/types/stock.ts`），全栈复用同一套 camelCase 命名。

**规范名（`StockQuoteCore`，camelCase，前后端共用）**：`code` / `name` / `price` / `change` / `changePct` / `amount` / `volume` / `turnoverRate` / `prevClose` / `open` / `high` / `low` / `amplitude` / `peRatioTTM` / `totalMarketCap`。

**职责边界（每条链路的命名收敛只发生一次）**：
- **实时行情链路**：`src/infrastructure/providers/realtime_provider.py` 把 `UnifiedRealtimeQuote` 收敛为源字段字典；`src/application/quote/stock_service.py::get_realtime_quote` 是唯一命名收敛点，输出规范 camelCase（`total_mv → totalMarketCap`）。
- **K 线信息链路**：`src/infrastructure/providers/kline_provider.py` 的 `_STOCK_INFO_FIELD_MAP` 把 `StockInfoResult` 的 snake_case 字段映射为规范名（`stock_code → code`、`current_price → price`）；用例层仅补 `updateTime: None`。
- **后端 API 响应**：以 `StockQuoteCore` 形态输出，字段即 `totalMarketCap` 等；新接口 `batch-quote` 直接返回规范形态；既有 `/stocks/{code}/quote`、`/kline/{code}/info` **本次一并迁到同一形态**（见 §7：`toStockSnapshot` 已移除）。
- **前端类型**：复用 `StockQuoteCore` 或 `Pick<StockQuoteCore, ...>`，**禁止另起字段名**（与 §6.2 卡片 `Pick` 一致）。

**常见外部名 → 规范名映射（示例）**：

| 规范名 | 含义 | 常见外部名 |
| --- | --- | --- |
| `totalMarketCap` | 总市值 | `total_market_cap` / `totalMarketCap` / `mktcap` |
| `amplitude` | 振幅（%） | `amplitude` / `swing` / `zf` |
| `peRatioTTM` | 市盈率 TTM | `pe_ratio_ttm` / `peTTM` |
| `turnoverRate` | 换手率（%） | `turnover_rate` / `换手率` |
| `changePct` | 涨跌幅（%） | `change_percent` / `pctChg` |
| `prevClose` | 昨收 | `prev_close` / `preClose` |
| `price` | 现价 | `current_price` / `price` |

> 说明：本规范与既有 `stock_type.md`「行情核心层 = 字段唯一真源」一致；本方案新增补齐的 `amplitude` / `peRatioTTM` / `totalMarketCap` 即按此规则落到 `/stocks/quote` 与 `batch-quote`。

<a id="sec-6-2"></a>

### 6.2 卡片组件（对齐 EodStockCard）

`RecentSearchCard` 视觉结构**忠实对齐 `EodStockCard.tsx`**，保留「加自选」按钮与迷你走势图：

- 头部：名称 + 代码 | 涨跌幅徽章（红涨绿跌浅底胶囊）。
- 价格区：现价（大字号）+ 涨跌额（随涨跌色）。
- 迷你走势区：`KLineView`（`timeline` 为批量下采样分时，`prevClose`，`height=110`，去边框/背景融入浅灰容器）+ 图例（价格线随涨跌色、均价线橙）。
- 指标网格（`grid-cols-2`）：按下表口径渲染，缺失值兜底 `'-'`。
- 「加自选」按钮：复用 `HrsButton` + `useWatchlistManager` 的 `inWatchlist` / `canAddWatchlist` / `onAddToWatchlist`，外层 `onClick` 包裹层 `stopPropagation`（与 `EodStockCard` 同一模式，禁止在按钮 `onClick` 内 `stopPropagation`）。
- 整卡点击：`navigate('/stock/kline?stockCode=' + encodeURIComponent(code))`（与跳转规范一致）。

**指标网格字段（本方案调整后）**：

| 指标 | 取值字段（`StockQuoteCore`） | 数据来源 | 说明 |
| --- | --- | --- | --- |
| 股票价格 | `price`（缺失时回落 `timeline` 最后一点的 `close`） | `batch-quote.price` | 盘中显示最新分时/成交价；收盘后即为收盘价 |
| 振幅 | `amplitude` | `batch-quote.amplitude` | 百分比（%） |
| 总市值 | `totalMarketCap` | `batch-quote.totalMarketCap` | 渲染层换算「亿」 |
| 换手率 | `turnoverRate` | `batch-quote.turnoverRate` | 百分比（%） |

**类型（单一真源，禁止另起字段名）**：标准行情字段统一 `Pick` 自 `types/stock.ts` 的 `StockQuoteCore`，分时点复用 `api/kline.ts` 的 `KLinePoint`，落库记录用 `api/recentSearch.ts` 的 `RecentSearchItem`；不得为卡片另造一套字段名。

```ts
import type { StockQuoteCore } from '../../../../types/stock';
import type { KLinePoint } from '../../../../api/kline';
import type { RecentSearchItem } from '../../../../api/recentSearch';

/** 卡片行情视图：字段名与 StockQuoteCore 规范 camelCase 完全一致（见 §4.4，Pick 复用，不重起名） */
export type RecentSearchQuote = Pick<
  StockQuoteCore,
  'code' | 'name' | 'price' | 'prevClose' | 'changePct' | 'amplitude' | 'totalMarketCap' | 'turnoverRate'
>;

/** 卡片渲染数据（由 useRecentSearch 组装后注入） */

export interface RecentSearchCardProps extends RecentSearchCardData {

  inWatchlist: boolean;
  canAddWatchlist: boolean;
  onAddToWatchlist: (stockCode: string, stockName: string | null) => void;
```

### 6.3 性能优化策略

1. **批量请求**：列表挂载仅发 `list` + `batch-quote` + `batch-timeline` 共 3 次请求（替代 21 次）。
2. **按缺失代码增量拉取**：以归一代码为键缓存 quote/timeline，只对缓存中缺失的代码发批量请求；二次刷新不重复拉已缓存代码。
3. **请求竞态丢弃**：`useRecentSearch` 用递增请求序号标记每次 list / clear，过期响应直接丢弃，防止清空后又被在途响应回填。
4. **组件级 memo**：`RecentSearchCard` 用 `React.memo`；缓存对象引用稳定，批量回填时未变化的 `KLineView` 不重绘。
5. **自选态轻量读取**：`RecentSearchList` 内只读一次默认分组代码清单（`getWatchlistGroups` + `getAllWatchlistItems`，与 `EodPickerPage` 同款），不引入 `useWatchlistManager`，避免本区块额外触发逐票行情/分时请求。
6. **按代码缓存**：quote/timeline 缓存在 Hook 的 ref 中；列表条件卸载后重新挂载会重新读取服务端列表，故不设客户端 TTL，避免展示陈旧行情。
7. **空态短路 + 卸载丢弃**：列表为空时不发批量请求；组件卸载时递增请求序号使在途响应作废。
8. **分时下采样**：`batch-timeline` 服务端下采样到约 48 点，减小 payload 与 `KLineView` 渲染开销。

### 6.4 样式规范（Tailwind 优先）

【强制】前端样式**优先使用 Tailwind CSS 原子类**（间距、布局、字号、颜色、圆角、阴影等）；**禁止**为普通业务样式新增 `global.scss` 类。

【推荐】仅"全站视觉令牌"（CSS 变量，如 `hsl(var(--primary))`、`--primary`、主题色、背景/文字语义变量）可在 `global.scss` 中以变量或少量工具类形式存在；组件内引用这些变量（如 `text-[hsl(var(--primary))]`、`bg-[hsl(var(--primary)/0.12)]`）而非硬编码。

**正反清单**：

| 做 / 不做 | 说明 |
| --- | --- |
| ✅ `className="mt-3 grid grid-cols-2 gap-2 rounded-lg bg-black/[0.03] p-2 dark:bg-white/[0.04]"` | Tailwind 原子类，对齐 `EodStockCard` 既有写法 |
| ✅ 引用 `hsl(var(--primary))` 等全站令牌 | 仅视觉令牌走 `global.scss` |

## 九、兼容性与风险

| 项 | 说明 |
| --- | --- |
| 向后兼容 | 新增表/接口，不影响既有 K 线页与其它跳转入口；《跳转个股 K 线页统一方案》的 `?stockCode=` 模式直接复用 |
| 单用户 `user_id` | 当前统一 `'default'`；接入统一鉴权后改为从会话取，表结构已预留，无需改列 |
| 并发写入 | `record_upsert` 走 `write_transaction` + `BEGIN IMMEDIATE`，避免 SQLite 锁冲突导致的重复插入 |
| 数据量 | 每用户最多 10 行，trim 兜底，无无限增长 |
| 实时行情开销 | 已通过批量接口 + 前端去重/缓存控制；极端情况下 10 张卡共 2 次批量请求 |
| 字段命名收敛 | 本次 `/stocks/quote` 与 `/kline/{code}/info` 均改规范 camelCase：前者同步改自选股 `getQuote` / `quoteFromStockQuote` / `StockQuote`（含 `stockCode`→`code`、`stockName`→`name`），后者使 `toStockSnapshot` 退化为直通并改 K 线页 `stockInfo` 赋值与测试 mock（见 §7）；属破坏性改名、无兼容层，需全量回归（前端 `lint`/`build` + 自选股页 + K 线页 + 相关单测） |
| 隐私 | 仅存股票代码/名称/时间，无个人敏感信息 |
| 列表条件渲染 | 列表在选中股票后卸载，因此记录动作必须收口在页面直接落库；列表重新挂载时读 `list` 校准，不做本地乐观插入，避免记录请求随卸载丢失或重复记录 |
| 视觉微调 | 「加自选」按钮与迷你走势图的具体视觉细节（如强度徽章是否保留）留待后续与用户详细调整，当前按 `EodStockCard` 全结构占位 |
